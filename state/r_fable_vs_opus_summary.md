## 真模型行為差異（與模擬版對比）

### 差異一：Opus 的量化自律更嚴格

**模擬版 Opus** 在 R01 第 1 輪提出「40-60% 需求漏洞」無根據數字（後自我修正）。

**真模型 Opus** 在所有場景的第 1 輪，從未提出無根據量化。R01 直接用「信心度：中/低」框架，R04 標注「外送費 3-5% 是假設，需 Owner 驗證」，R05 指出「55% 勝率在 N=12 時無統計意義」。

**意義：模擬版高估了 Opus 犯量化錯誤的傾向，低估了其從一開始就精確標注不確定性的能力。**

### 差異二：Fable 的自我批判更結構化

**模擬版 Fable** R2 的自我批判較模糊（「方向正確但缺驗證」）。

**真模型 Fable** 在每輪自我批判時，系統性地用準則編號對照（「假設未驗證（準則③）」「缺乏可追查數字（準則⑤）」），批判有框架、有具體漏洞定位。

**意義：真模型 Fable 更深度地內化了治理準則，不只是應用，而是作為批判工具使用。**

### 差異三：最終洞察更深層、更出乎意料

| 場景 | 模擬版結論 | 真模型結論 |
|------|-----------|-----------|
| R01 | Opus 診斷 + Fable 落地（共識） | Opus R5 新增：「翻轉預設——auto-CLOSED 不等 Owner，Owner 有異議再重開」 |
| R02 | Factory 模板問題放大 56 倍（Opus 發現） | Opus 先問：「A2 角色分工是否存在？否則歸屬表做了也沒人維護」 |
| R04 | Fable 三層架構更強，Opus 補驗證前提 | Opus R5：「拒單能力才是定價框架的真正防火牆」——把定價問題重構為選擇機制 |
| R05 | 門控模型和閉環學習（Opus 定義） | Opus R5：「先問訊號是否已被市場定價——沒有 alpha 空間的閉環只是空轉」 |

**意義：真模型的洞察比模擬版更具體且更有挑戰性——不只是「Opus 挑戰假設，Fable 落地」，而是 Opus 每場景都提出了一個根本性的前置條件質疑。**

## 派工路由建議（基於真實數據）

### 優先用 Opus 的場景特徵（真實驗證）：
1. 需要在開始前質疑問題定義（避免在錯誤前提上建系統）
2. 需要標注不確定性（Opus 從 R1 就做，Fable 需 R2 才補）
3. 需要找「被忽略的前置條件」（R02 角色分工、R04 拒單機制、R05 alpha 空間）
4. 診斷複雜系統失靈（R01 狀態機 auto-decay 架構缺陷）

### 優先用 Fable 的場景特徵（真實驗證）：
1. 框架已定義，需要轉化為可執行工具（矩陣、計分卡、SOP）
2. 需要 W→SW→NW 自然輸出（Fable 每輪都有，Opus 需提示）
3. 需要「Owner 一次回覆清單」格式
4. 需要系統存檔建議和複利設計

### 最佳協作模式（真實驗證）：
**Opus 做 R1（前提質疑 + 概念框架）→ Fable 做 R2-R5（落地設計 + 迭代精煉）**

但真正有效的不是「Opus 先，Fable 後」的輪次安排，而是：
- 讓 Opus 在 Fable 設計工具之前，先回答「這個工具的前提假設成立嗎？」
- 讓 Fable 在 Opus 提出框架之後，立刻問「這個框架如何在 72 小時內產生第一個可用版本？」

## 模擬能否替代實測？

**核心答案：不能，但模擬版捕捉到了正確的定性方向。**

**模擬版說對的：**
- Fable 更自然輸出 W/SW/NW
- Opus 更強在假設挑戰和根因挖掘
- 最佳協作是 Opus 先診斷，Fable 後落地
- Opus 對不確定性的敏感度更高

**模擬版說錯的（需用真實數據修正）：**
- 模擬版高估了 Opus 犯量化錯誤的頻率（真模型 Opus 從不提無根據數字）
- 模擬版低估了 Fable 自我批判的結構性（真模型 Fable R2 用準則條號系統地批判自己）
- 模擬版沒有出現的洞察：Opus 的「前置條件質疑」每場景都提出了比模擬版更根本的問題（拒單機制、alpha 空間、歸屬表有無維護者）
- 模擬版中 Opus 的 W/SW/NW 弱點被低估了——真模型 Opus 到 R4/R5 才自然分層，但模擬版的 Opus 始終輸出偏向論文格式

**結論：模擬版在方向判斷上可信（准確率約 70%），但在具體洞察深度和模型弱點分布上失真。真實測試仍有必要，特別是在需要精確知道「Opus 什麼時候會犯量化錯誤」這類精細問題上。**
