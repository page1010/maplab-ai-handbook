# A6 LINE 銷售對話狀態機 — SOP 拆解
> 版本：v0.1 | 建立：2026-06-23 | 來源：62 筆 confirmed 對話樣本抽樣分析
> 本地使用、去識別化、不外傳、不 push

---

## 狀態總覽

```
S0_OPENING → S1_INQUIRY → S2_DATA → S3_QUOTE → S4_BOOKING → S5_PAYMENT → S6_PREDAY
                                         ↑               ↑
                               S1_QUALIFY（釐清路徑）  S4_BOOKING_ASK
                               外帶自取 → 另一分支
```

---

## S0 — 開場（Opening）

### 觸發條件
- 客戶第一次發訊息給 LINE OA（加好友 / 初次接觸）

### Account 標準回法
```
[客戶名]您好！
[自動歡迎訊息：品牌介紹 + 服務分類 #1-#9 選單]
```

- 自動回覆先觸發，包含品牌介紹（旅圖 8 年、台南在地等）+ 服務分類
- Mina 通常在幾小時內補一則「您好，」人工跟進
- 客戶不需要回任何關鍵字，自動觸發

### 注意事項
- 此階段業務**不詢問任何問題**，只給資訊
- 若客戶當天不回覆，不追問
- 自動回覆覆蓋大部分非營業時間

## S1 — 詢價意圖偵測（Inquiry Intent）

### 觸發條件（客戶端）
| 觸發詞/語句 | 類型 |
|---|---|
| 「外燴服務」、「想詢問外燴」、「請問外燴」 | 直接詢價 |
| 「開幕餐點」、「開幕活動」 | 場合型 |
| 「週歲到府」、「寶寶性別派對」、「抓周外燴」 | 場合型 |
| 「茶點」、「茶會」、「咖啡茶點」 | 場合型 |
| 「外帶自取」、「單點」 | 另一路徑（外帶） |
| 直接給日期+人數 | 跳 S2 |

### Account 回法 A（詢價意圖確認，需釐清）
```
您好，
外燴餐點屬於客製化服務，
[補問：日期/人數/場合]
```

### Account 回法 B（意圖明確，直接給報價框架）
```
這邊先幫您做報價介紹
[如有需求請提早預約]
[★ 服務範圍模板]
```

### 外帶自取分支
- 回傳：外帶菜單照片 + 外帶預訂時間
- 不走外燴報價流程
- 低消標準不同（外燴低消一萬起，外帶無低消限制）

### S1 → S2 轉換條件
- 客戶表達有外燴需求且非外帶 → 進 S2

---

## S2 — 資料收集（Data Collection）

### 必收欄位
| 欄位 | 典型問法 | 是否必填 |
|---|---|---|
| 日期 | 自然給出 or 業務問「請問活動日期」 | 必填 |
| 人數 | 「25-30 是大約賓客人數嗎」 | 必填 |
| 活動形式 | A 輕食/B 主食 | 必填（影響低消計算）|
| 場合類型 | 開幕/週歲/茶會/派對等 | 重要（影響菜單風格）|
| 場地 | 室內/室外/地址 | 重要（影響車馬費/布置）|
| 禁忌食材 | 「有任何禁忌食材嗎？比如蔥、蒜、豬肉」 | 詢問（可空）|
| 預算 tier | 後期問（選價位）| 後期必填 |

### 業務補問策略
- **一次問一個**，不要一次列清單
- 優先問日期（影響檔期確認）
- 其次問人數（影響報價計算）
- 禁忌食材在快送菜單時問

### 已有資料就不重複問
- 客戶在 S1 已給日期/人數 → 直接跳過，確認即可

### S2 → S3 轉換條件
- 日期 + 人數 + 大致形式都齊 → 進 S3

---

## S3 — 報價介紹與菜單確認（Quote Intro & Delivery）

### S3a — 報價介紹
固定模板：「★Map外燴整體規劃的服務範圍：」

實際格式（固定）：
```
(A.) XX人份 輕食茶點形式
[或]
(B.) XX人份 主食飽足感形式

★Map外燴整體規劃的服務範圍：[7點服務模板]

如有需求請提早預約！
目前這天場次預訂較多，請提早確認。
```

### S3b — 客戶選價位
- 客戶通常說：「一萬左右」、「預算 15000-16000」、「我想依照 1 萬」
- 業務確認：「我們低消是一萬起」（如果低於一萬要婉拒/調整）

### S3c — 菜單草稿
- 業務發送菜單草稿（照片已傳送）
- 詢問追加：「需要提供哪一個價位」、「有幾道甜點要調整嗎」
- 客戶可要求換品項（「不要蝦排，可以換什麼」）→ 業務給替代品

### 關鍵數字
- **低消**：一萬元起出車
- **預訂建議**：至少 10-15 天以上
- **超量因子（buffet）**：每道 15-20 份確保足量

### S3 → S4 轉換條件
- 客戶確認菜單/價位 → 業務問姓名電話

---

## S4 — 訂單建立（Booking）

### S4a — 請客戶提供聯絡資訊
```
請幫我們提供貴姓、電話建檔，
```
或
```
幫我留一下姓名電話，先為您登記
```

### S4b — 業務送匯款資訊
```
下方提供匯款資訊給您
[匯款帳號模板]
```

同時發送：
- 完整訂單確認（照片或文字）
- 活動場地確認（「請問是在自家嗎？還是交誼廳？」）
- 到場時間確認

### 訂金標準
- 通常 NT$3,000 起訂
- 客戶匯款後會傳：「我已經轉帳 NT$X 元給您，請您查詢存款明細！」

---

## S5 — 付款確認（Payment）

### 觸發
- 客戶傳匯款截圖或文字確認
- 系統/客戶的 LINE Pay 通知

### Account 回法
```
已查收，謝謝
```

### 後續收集
- 場地照片（用於陳列規劃）
- 桌面尺寸
- 活動到場時間 / 撤場時間
- 場合是否有蛋糕/特殊品項

## 分支：冷拒或流失

### 常見流失點
| 時機 | 客戶說 | 業務後續 |
|---|---|---|
| S3 後 | 「謝謝我們討論一下」、「考慮一下」 | 傳貼圖，不追問 |
| S3 後 | 「跟老公討論一下」 | 傳 OK，等客戶主動 |
| S2 | 「請問要提早多久預約」 | 告知最早確認方式（付訂） |

---

## 特殊情境

### 客戶直接問菜單/價格（跳過詢問）
- 業務回：「我們沒有制式化菜單，是以所需份數做報價」
- 引導說出人數 + 形式

### 客戶說預算不夠
- 若低於一萬：「我們低消是一萬起出車」→ 介紹外帶自取
- 若在一萬附近：給一萬版菜單

### 客戶改窗口
- 「我請 XXX 統一窗口好了」→ 業務回「好」，等新窗口聯繫

## 資料缺口（訓練層面）

| 階段 | 樣本量 | 缺口說明 |
|---|---|---|
| S0 開場 | 充足（37+ 對） | — |
| S1 詢價意圖 | 中（22 對） | 需更多場合類型（婚禮/公司尾牙）|
| S2 資料收集 | 中（18 對） | 多輪補問序列較少 |
| S3 報價 | 充足（37+ 對） | — |
| S4 訂單建立 | 少（4 對） | **缺口：需更多確認+匯款對話** |
| S5 付款確認 | 少（5 對） | **缺口：需更多付款後互動** |
| S6 活動前 | 少（2 對） | **缺口：需日前/當天協調樣本** |
