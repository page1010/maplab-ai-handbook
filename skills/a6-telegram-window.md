## 一、窗口定位

| 項目 | 說明 |
|------|------|
| **誰用** | 業務（Mina 等），不是客人 |
| **在哪用** | Telegram — 向 A6 下指令 |
| **目的** | 快速產報價草稿 + 記錄修改行為 → 優化 A5 |
| **A6 不做** | 跟客人說話、自己算報價（一律調 A5）、替業務決定 |

---

## 二、指令格式

### 2.1 急件報價（最常用）

```
格式：報價 [客戶名] [活動類型] [人數] [預算/備註]

範例：
報價 王小明 婚禮 80人 預算6萬
報價 林太太 週歲 50人 要素食
報價 ABC公司 企業尾牙 200人 需要場地建議
```

A6 動作：
1. 在 SALES_INTAKE 建一筆（case_id 自動產生）
2. 調用 A5 → 用 createQuote 產出報價草稿
3. 把所有 A6 對話寫入 CONVERSATION_LOG（source=Telegram, speaker=A6）
4. 回傳報價草稿摘要 + Sheet 連結

---

### 2.2 品項修改指令（「你幫我把...改成...」）

#### 場景模擬

**業務說：** 你幫我把主菜換成素食版本

**A6 處理流程：**

```
Step 1 — 確認 case_id
  → 若有 active 報價：「請問是哪個案件？輸入 case_id 或客戶名稱」
  → 若業務已說明：直接進 Step 2

Step 2 — 查 A5 Items 表
  → 找「主菜」相關品項（A5 MAIN 系列）
  → 找「素食」相關品項
  → 若 Items 表有對應品項：輸出 diff
  → 若沒有：回報「Items 表無素食主菜，請補充品項或確認名稱」

Step 3 — 輸出確認差異
  原：MAIN003 雞腿排 × 80人 = $12,000
  改：MAIN047 蔬食塔可 × 80人 = $9,600（差 -$2,400）

Step 4 — 業務確認後
  → 寫入 REVISION_LOG：
    section=品項, original=MAIN003, revised=MAIN047,
    change_type=修改品項, reason_tag=客戶要求
  → 更新 QUOTE_WORKBENCH 對應欄位
  → 寫入 CONVERSATION_LOG（B層）
```

#### 完整指令模式對照表

| 業務說 | A6 動作 |
|--------|---------|
| 你幫我把X改成Y | 查 Items 表 → diff → confirm → REVISION_LOG |
| 幫我去掉X | 從報價刪除 → 重算小計 → REVISION_LOG |
| 加一個X | 查 Items 表是否存在 → 加入 → REVISION_LOG |
| X換Y | 同「改成」 |
| 換素食版本 | 搜尋 Items 表 vegetarian/素食標籤，逐一替換 |
| 改人數為X人 | 重算所有數量相關品項 → 輸出 diff |
| 套XXX方案 | 查 a6-rapid-quote-sop.md 活動類型模板，整批替換 |

### 2.4 補問清單觸發

補問邏輯：**只有必問欄位缺失時才列補問清單**，其他欄位先填「待確認」繼續出報價。

**必問（影響毛利率，缺一不可）：**
- 活動類型（event_type）
- 人數（pax）
- 品項偏好（甜鹹比例）
- 預算（budget）

**先填待確認（不影響毛利率，可後補）：**
- 地址 → D3 填「待確認」，車馬費 E30 填 $0 暫不算
- 時間 → F3 填「待確認」
- 門牌/樓層 → 備註填「待確認」
- 合約版本 → 依客戶名自動判斷，不列補問

當有必問欄位缺失時，A6 主動輸出：

```
[補問清單] 以下資訊需要確認才能出報價：
□ 確認人數（目前說「大概80人」）
□ 預算區間？
```

## 三、對話紀錄規則

每一輪 A6 互動都必須寫入 CONVERSATION_LOG：

| 欄位 | 值 |
|------|----|
| source | Telegram |
| speaker | A6（A6 輸出）或 業務名稱（業務輸入） |
| case_id | 對應 SALES_INTAKE |
| message | 原文 |

> **這是 B 層 Collaboration Log 的核心資料。** 業務↔A6 的每次互動都是未來優化 A5 的訓練素材。

---

## 四、與 A7 自動回覆的連接

未來當 A7 有足夠 CONVERSATION_LOG 資料後：
- A 層（LINE 客人↔業務）→ 訓練 A7 FAQ 自動回覆
- B 層（業務↔A6）→ 優化 A6 報價指令理解 + A5 品項精準度

**交叉比對邏輯：**
```
同一 case_id 下：
  A層：客人說「我想要比較輕的菜色，不要太油」
  B層：業務告訴 A6「把主菜改成蔬食版」
  → 學到：「輕食需求」觸發「蔬食替換」行為
  → A6/A5 下次遇到相似需求可提前建議
```
