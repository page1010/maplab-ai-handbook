## Telegram bot 和這裡（Claude Code terminal）的關係

**架構：Telegram bot 是一個轉發站，不是獨立邏輯。**

```
Mina 手機 → Telegram bot (bot_a6.py) → claude -p → Claude API → 回傳答案
```

`bot_a6.py:234` 的核心是呼叫 `claude -p`，把業務訊息 + system prompt + 對話記錄丟給 Claude，拿到回覆再傳回 Telegram。

### 邏輯一致性取決於：

| 項目 | 來源 | 一致嗎？ |
|------|------|----------|
| 身份 prompt | `recalls/A6_recall_compact.md`（20 行） | **一樣**，這裡的 system prompt 也是這份 |
| 對話記憶 | `conv_history_a6.json`（最近 20 輪） | **獨立**，Telegram 有自己的 history，這裡有自己的 |
| 可用工具 | bot 用 `claude -p`（無 MCP、無 tool） | **不一致** — bot 端的 Claude **沒有 Sheets/Drive MCP**，不能真的寫入 Sheets 或建報價單 |
| 模型版本 | 取決於 `claude -p` 預設 | 可能不同，看 Claude Code 設定 |

### 最大落差

**Telegram bot 裡的 Claude 沒有 MCP 工具**，它說「已寫入 QUOTE_DRAFT」其實**做不到** — 它只能輸出文字建議，不能真的操作 Google Sheets。

### 怎麼確認

1. **看 prompt**：`cat recalls/A6_recall_compact.md` — 這就是 bot 餵給 Claude 的全部指令
2. **看對話記錄**：`cat bot_a6/conv_history_a6.json` — bot 的對話 context
3. **看 log**：`cat data/a6-logs/$(date +%Y-%m-%d).md` — 每次對話都有紀錄
4. **測試**：在 Telegram 問同樣的問題，對比這裡的回答

如果你要確保 Mina 在 Telegram 拿到的報價是**真的寫進 Sheets** 的，需要：
