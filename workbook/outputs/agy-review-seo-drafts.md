## (a) 方向確認

### 1. 兩篇草稿的 SEO 定位與優先級合理性
*   **結論**：**完全合理且優先度極高**。
*   **分析**：

    *   `gap1-hotel-meeting-tea.md` 精確鎖定了 `GAP-1`（飯店場域會議茶點案例），主攻 `台南飯店會議茶點外燴`，對齊了富信飯店社工公會會議的 Drive 案例素材。

### 2. 互搶計畫（seo-cannibalization-plan.md）的 Pillar 選擇合理性
*   **結論**：**非常合理。目前 `tainan-catering-venue-guide`（台南外燴場地指南）是最佳的 Pillar 候選，無更合適者。**
*   **分析**：
    *   **排除 Page 15 (`tainan-party-venue`)**：雖然 WP 的 Page 權重通常較高，但該頁的主題是「派對流程、餐點、預算」，屬於 broader intent。若強制將其改造為純外燴場地 Pillar，會稀釋其原本在派對規劃上的關鍵字權重，且 slug 語意不對稱。
    *   **排除 `tainan-catering-venue-selection-2026`**：帶有「2026」年份限制，不適合作為長青（Evergreen）Pillar。
    *   **排除拼音/重複頁**：`tainan-waihui-changdi-tuijian` 與 `tai-nan-wai-hui-chang-di-tui-jian` 拼音冗長且可能為重複頁面，不符合現代 SEO 友善網址規範。
    *   **選擇 `tainan-catering-venue-guide` 的優勢**：Slug 語意精確且 Evergreen，專注於「外燴場地指南」，非常適合作為 Hub 樞紐，向下連結「7選清單（`venue-7`）」、「2026 選場注意事項（`selection-2026`）」以及派對流程，形成健康的 Topic Cluster（主題集群）結構。

### 3. 301 vs 改寫子意圖的取捨與遺漏考量
*   **優點**：計畫中對於 Page 15（保留並轉為派對流程）與 `venue-7`（保留為清單型 supporting page）的改寫決策相當正確，避免了粗暴 301 導致的內容流失與關鍵字覆蓋率縮減。
*   **遺漏考量**：
    *   **GSC 實質歷史排名與流量確認**：在將拼音頁（如 `tai-nan-wai-hui-chang-di-tui-jian`）301 重定向至 Pillar 之前，必須在 Google Search Console (GSC) 確認該拼音頁是否已有穩定排名或外部反向連結（Backlinks）。若該頁反向連結多且為流量主力，需格外小心重定向初期的流量波動。
    *   **資料庫層面的舊連結清理**：實施 301 後，全站既存文章內指向舊 slug 的內鏈並不會自動更新，會造成伺服器重定向負擔（Redirect Hop）。應在計畫中補上「需在 WP 後台執行批次替換，將指向舊頁面的內鏈直接更新為新 Pillar 連結，避免 Redirect Chain」的步驟。

## (c) 補盲點

### 1. 草稿可能遺漏或寫了「不應該說」的事（捏造細節）
*   **盲點**：兩篇草稿為了避免「捏造 Drive 素材細節」，目前在描述「富信飯店社工公會會議」與「醞舞流/說事實開幕」時**極度簡略**，幾乎僅提到「作為事實基礎，不延伸推測菜單內容」。
*   **修正建議**：對 B2B 買家而言，若案例文章完全沒有寫出「當天提供哪些品項」或「如何排除現場困難」，文章會顯得過於空洞，變成純粹的理論指南。
    *   *預防措施*：在正式發布前，A2/經辦人必須向 Owner 索取該場次的「**實際菜單大類（例如：手拿鹹點、無酒精調飲、常溫甜點）**」與「**照片特寫中呈現的品項名稱**」進行回填，既能維持事實真實性，又能豐富文案內容。

### 2. 遺漏的 FAQ 問題（買家痛點）
*   **飯店會議（gap1）FAQ 盲點**：
    1.  *飯店場地通常有「禁帶外食」或「需收清潔費/保證金」的規定，外燴團隊如何配合？*（B2B HR 必問：MAPLAB 能否提供進場切結書、清運證明、或配合飯店窗口溝通？）
    2.  *費用是否包含垃圾清運與場地還原？*（飯店對場地清潔要求極嚴格，需說清 MAPLAB 負責到什麼程度。）
*   **開幕茶會（gap2）FAQ 盲點**：
    1.  *公開的開幕活動中，若來賓有臨時的飲食禁忌（例如：全素、無麩質、孕婦忌口），菜單如何配置？*（買家最怕現場貴賓沒東西吃。）
    2.  *如果開幕剪綵或致詞流程延遲，外燴服務人員的撤場時間與超時服務費怎麼計算？*

### 3. 互搶計畫沒想到的 Edge Case
*   **外部連結（Backlink）流失風險**：若 `tainan-waihui-changdi-tuijian` 過去曾被在地部落客或合作夥伴引用，直接將其 301 重定向可能在短期內導致該頁面的權重無法 100% 傳遞給新 Pillar。在進行 301 前，應利用 GA4 / Search Console / Ahrefs 等工具確認是否有高價值外部連結，若有，需在重定向設定中確保為 `301 Permanent Redirect`，且不可隨意撤除。
*   **Redirect Loop & Chain (重定向鏈)**：由於存在複數個拼音/重複 slug（`tainan-waihui-changdi-tuijian` 與 `tai-nan-wai-hui-chang-di-tui-jian`），設定重定向時必須是一對一直接指向 `tainan-catering-venue-guide`。禁止出現 `tai-nan...` -> `tainan-waihui...` -> `venue-guide` 的多跳重定向，這會顯著消耗 Google 的 Crawl Budget（抓取配額）。

### 4. 發布前需補的資產與確認程序
*   **隱私與肖像權確認**：Drive 案例照片中，若拍到來賓的清晰正面肖像，必須進行模糊化處理，或者確認主辦方已獲得肖像權授權。B2B 企業客戶非常注重隱私與商譽，避免露出可識別的來賓面孔。
*   **Codex REST 數據回填確認**：互搶計畫的第 1 步「最優先」為「匯出六頁的 REST 狀態」，需確實執行並取得 GSC 實際流量數據，確認哪一個拼音頁才是搜尋引擎眼中的 Canonical 頁，再做最終的 301 決策。

## 綜合結語與建議優先序

綜合本輪審查，兩篇草稿的 SEO 設定方向準確，語氣克制專業，完美避開了所有品牌語氣地雷。互搶計畫在架構上是正確的，但需要引入更嚴格的數據確認與技術防範措施。

### 建議執行優先序：
1.  **【高優先・數據安全】** 執行 `seo-cannibalization-plan.md` 中的 §7 Codex 盤點，使用 WP REST API 匯出這 6 個場地頁面的歷史流量、真實 Canonical 設定與 indexability，避免盲目 301 造成流量損失。
2.  **【中優先・文案增值】** 對照 `gap1` 與 `gap2` 草稿，由 A2/經辦人根據 Google Drive 實體照片或出貨明細，填補具體的「餐點品項大類」與「現場動線配置細節」，並將上述「飯店限制配合」與「飲食禁忌」FAQ 補入文稿中。
3.  **【中優先・視覺準備】** 根據兩篇案例的特點，建立 Visual Brief，通知設計/視覺人員在 WP 後台排版時，套用「深橄欖 + 暖米 / 暖棕 + 淺米灰」的企業商務色系。
4.  **【低優先・上線發布】** 提交完整修正稿（含真實照片與核實內鏈）獲取 Owner Approval 後，於 WordPress 執行排版上線，並同步設定 301 重定向。
