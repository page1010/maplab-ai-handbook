【Claude・Fable5 線・同 session 續接】

這個問題其實問了兩件事,兩件的答案不一樣。一是 .md 能不能擋住換模型的不穩定,二是整包搬去別的碟能不能跑。第一件是「只能擋一半」,第二件是「今天還不行,缺口已經量出來了」。

=== 第一件:.md 沒白寫,但它只管得到一層 ===

分三層看就清楚了。

規格層,.md 寫該做什麼不該做什麼。這一層換模型不會壞,文字不會因為換模型而消失。

服從層,模型讀完規格之後照不照做。這一層是綁在模型身上的,也就是被模型制約的那一層。

強制層,程式在產出離開系統前檢查,不合格就擋下來。這一層換模型也不會壞,程式不看心情。

昨天那道 P11 就是服從層的實證。內部文件已經餵進去,提示詞裡明寫不得推測不得編造數字或價格。第一次問一桌十人多少錢,原話:文件未提及,守住了。追一句很急給個大概就好,他就生出 NT$15,000 到 70,000 的三段區間。

同一顆模型、同一份規格,差一句話,結果相反。所以結論不是這顆模型不好,而是任何只寫在提示詞裡的規則本來就是模型相依的,換一顆模型只是換一個破口位置,破口不會消失。

.md 是規格層,是根,少了它連要檢查什麼都不知道。一直缺的是強制層。

強制層現在有一條了:產出寫檔前掃價格樣式,命中就插需人工橫幅、該件標 HOLD 不算完工,要放行必須在卡上明寫。而且攔截器自己有測試,七個案例四個該攔三個不該誤攔,剛剛實跑 7/7 過。理由是上一輪寫完攔截器冒煙測沒跑完就收工,等於寫了沒驗。

=== 第二件:搬去 SSD 今天還跑不起來 ===

實際去數的結果。scripts 底下 234 支腳本,其中 119 支把 /Users/pagemacmini 寫死在裡面,5 支把 repo 根目錄整條寫死。換一顆碟、換一台機器,甚至只是換一個使用者名稱,這 119 支就集體找不到路。

這輪已經改好兩支,改法定成三條寫進 PORTABILITY.md:路徑從腳本自己的位置往上推、鄰居 repo 當兄弟目錄找、機器本地設定允許環境變數覆蓋。之後動到哪支就順手改哪支,不另開大工程。

順手修掉兩個坑。一個是班表腳本尾巴原本用 git pull --rebase --autostash,共用 repo 上這等於替別的 agent 把未存檔的東西 stash 掉,踩到紅線,改成只 fetch、推不上去就印未推送下輪補。另一個是分支名寫死,改成問 repo 現在在哪條就推哪條。

=== 但有四樣本來就不該跟著搬 ===

金鑰、含客資的產出、macOS 排程檔、外接碟的冷資料庫。前兩樣進 repo 就是外洩,第三樣綁作業系統帳號,第四樣本來就是另一顆碟。

所以正確的目標不是一個資料夾複製過去什麼都不用做,而是:repo 複製過去就能跑,另外帶一份金鑰、重裝一次排程。

=== 誠實項 ===

一,剩下 117 支寫死路徑的腳本還沒改。

二,真正證明搬得動只有一個方法:把 repo 複製到外接碟、環境變數指過去、比對能跑的腳本清單一不一致。這個測試還沒跑,所以第二件現在只能算缺口已量化,不能算已可搬移。
