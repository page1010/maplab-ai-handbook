# 加購道具服務 AOP v1.0（範例案=小肚肚開幕案）

**這是什麼**:客戶在外燴案加購實體道具（剪綵用具、打卡立牌、插旗、緞帶等）時的
標準作業程序。Owner 5166（2026-09-11）裁定以小肚肚開幕案為範例建立。
定位:道具不是「叫客戶自己買」的建議,是**我們的加值服務品項**——採購、客製、
到場配置整包,直接入報價單。

## 流程八步

1. **需求入檔**:客戶/Owner 提出加購 → 當回合寫進案件 TASK_BRIEF 事實表（含 msg id）。
   案件無 TASK_BRIEF → 先建（task-brief-ssot 規則）。
2. **選品**:優先序=vendor-db 既有紀錄 > Owner 指定賣場 > 新調研。
   反編造紅線:賣場/連結必須真實出現在紀錄或搜尋結果,絕不虛構帳號與價格。
3. **定價**:外部品項照 5032 裁定規則加成得對外價;基礎價格帶與推算明細**只存案件
   TASK_BRIEF（內部檔）**;對外檔零「成本/毛利/x1.35」字眼（quote-package-skill 自檢閘）;
   查無價=標「報價確認中」,絕不編價;幣別 TWD。
4. **入報價單**:每項一列,品名寫「服務」不寫賣場;備註欄必寫**確認死線**——
   客製來圖項=活動日前 **14 個工作日**確認並提供 logo 圖檔（含設計稿一來一回）;
   現貨項=活動日前 **10 個工作日**確認。死線從案件事實表的活動日推,改期跟著改（5165 教訓）。
5. **slide 展示**:加購頁每項一格=示意圖＋一句「帶來什麼」（儀式感/打卡擴散/品牌識別）
   ＋對外價＋確認死線。內部圈選版可用賣場參考圖;**正式對外版必換自家實拍或設計版位**
   （平台截圖與他人商品照不得對外）。
6. **下單**:Owner 端執行,bot 不代買;交期以賣場聊聊白紙黑字為準,死線倒推留備貨餘裕。
7. **到貨與使用**:到貨檢查 → 活動日配置 → 活動實拍回填素材庫（供 slide/網站換自家圖）。
8. **失誤回路**:交期保不住 → 啟動備案（素面現貨/本地印刷急件當面取件),備案進對客版
   前必經 Owner 圈選。
