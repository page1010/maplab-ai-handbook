## 狀態（舊）
🔲 暫停（2026-04-07 重新規劃方向）

## 原本目標
拿「客人 ↔ 業務」+「業務 ↔ A6 內部協作」雙向完整對話，用來：
1. 訓練 A6 客服回覆模型
2. 優化 FAQ 模板
3. 分析客戶常見問題
4. 改進報價流程

## 為什麼原本以為要拆 Sheet
- LINE webhook 寫入 CONVERSATION_LOG，跟報價系統共用同一個 Spreadsheet（1fn_woqYI...）
- 擔心對話量大會影響報價系統效能
- 想拆出獨立 Sheet 純做訓練資料來源

## 原本拆 Sheet 計畫
1. 建新 Spreadsheet「MAPLAB_LINE_對話記錄」
2. 移 144 筆現有資料
3. 改 LineWebhook.js 的 SHEET_ID
4. 改 bot_a6.py 讀取目標
5. 部署新版 webhook

## 為什麼暫停（2026-04-07 發現的關鍵問題）
**LINE webhook 只能收到客人傳給品牌帳號的訊息，收不到業務從手機回的訊息。**

技術原因：
- LINE Messaging API webhook 觸發條件：客人主動發訊息給 OA → webhook
- 業務從 LINE Official Account Manager 後台回的訊息 → 不會觸發 webhook
- 結果：CONVERSATION_LOG 只有半邊對話，**沒有業務回覆**

訓練資料價值極低：
- 看到客人問「請問週六有空嗎」但看不到業務怎麼回的
- 無法分析「業務回覆風格」
- 無法用來訓練 A6 模仿業務語氣

## 新方向
**改用 LINE OA 後台「對話記錄匯出」CSV：**
1. 定時手動或排程從 LINE Official Account Manager 後台匯出對話 .csv
2. .csv 包含完整雙向對話（客人 + 業務回覆）
3. 把 .csv 上傳到 Drive 某個資料夾
4. A6 訓練流程從 .csv 讀，不再依賴 webhook 即時資料

## 拆 Sheet 計畫的重新評估
- 既然訓練資料來源變成 .csv，CONVERSATION_LOG 不再是訓練用途
- CONVERSATION_LOG 維持「只當 webhook 即時 log」即可
- 144 筆資料對報價系統效能影響為零（離 Google Sheets 上限差很遠）
- **拆 Sheet 不是必要的**

## 待釐清
1. LINE OA 後台匯出 .csv 的方式（手動 vs API）
2. 匯出頻率（每天 / 每週 / 即時）
3. .csv 存放位置（Drive 哪個資料夾）
4. A6 訓練流程是否真的需要這些資料？還是有其他更好的訓練來源？

## 不該做的事
- ❌ 拆 CONVERSATION_LOG 到獨立 Sheet（做了也沒用）
- ❌ 強化 LINE webhook 想「補抓業務回覆」（API 不支援）
- ❌ 在 CONVERSATION_LOG 上做訓練資料分析（資料殘缺）
