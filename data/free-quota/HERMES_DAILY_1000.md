## §1 每件 job-run 花多少次來回(實測,今天的數字)

今天跑了 5 件扇出 job-run,`calls=20`,**平均 4.0 次 API 呼叫 / 件**。
組成:產稿 1 次 + 換模型審稿 1 次 = 2 次為理論值;鏈上前幾顆免費模型常常直接失敗換下一顆,實測會變成 4 次。

於是 Owner 給的三個數字直接把 1000 這個目標算出來:

```
生圖  50 件 × 4.0 = 200 次
整理 100 件 × 4.0 = 400 次
生歌 100 件 × 4.0 = 400 次
─────────────────────────────
合計 250 件      = 1000 次來回 / 天
```

**Owner 那三個數字本身就等於 6092 要的 1000 個來回**,不必另外湊。
`MAX_CALLS` 已從 120 提到 **1100**(`FQ_MAX_CALLS` 可覆寫),另加「連續 8 次全模型失敗就收工」的斷路器,
免得撞到免費額度牆之後還空轉幾百次。

## §3 每日時段安排

一次跑 250 件會連續佔住機器好幾個小時,所以分 **6 班**。用法:

```
bash scripts/free_quota_daily.sh <第幾班> <共幾班>
```

| 時段 | 指令 | 這一班跑什麼 | 件數 | 來回數 |
|---|---|---|---|---|
| 07:00 | `free_quota_daily.sh 1 6` | 單件題目(場景 4-7)+ 三大扇出的第 1/6 | 4 + 42 | 約 184 |
| 10:00 | `free_quota_daily.sh 2 6` | 三大扇出的第 2/6 | 42 | 約 168 |
| 13:00 | `free_quota_daily.sh 3 6` | 三大扇出的第 3/6 | 42 | 約 168 |
| 16:00 | `free_quota_daily.sh 4 6` | 三大扇出的第 4/6 | 42 | 約 168 |
| 19:00 | `free_quota_daily.sh 5 6` | 三大扇出的第 5/6 | 42 | 約 168 |
| 22:00 | `free_quota_daily.sh 6 6` | 三大扇出的第 6/6 + 每週檢討(週一) | 42 | 約 168 |
| **合計** | | | **250 件** | **約 1024 次** |

分班規則寫在程式裡,不是寫在這張表:
- 扇出題目用 `items[BAND-1::BANDS]` 切,所以每班拿到的是**跨題目均勻分布**的一份,不是同一個場景一次做完。
- 單件題目(沒有 `FANOUT` 的)**只在第 1 班跑**,避免一天重複六次。
- 每班各自記冪等簽章(`.queue_sig_YYYYMMDD_bN`),同一班當天重跑會跳過;佇列內容一改就會重跑。
- 題目池每天從**不同起點、用與池子互質的步長**跳著取,所以連著跑七天不會每天做同一批。

**尚未掛排程**:上面六行還沒進 launchd(現況三支 launchd 排程本來就有 exit 127 的病,#68)。
掛之前先手動跑滿一天,確認免費額度撐得住(見 §5)。

## §4 品質怎麼守(不是靠「我覺得可以」)

1. **餵資料的題目一律附鐵律**:「只根據文件內容回答;文件沒寫的一律寫『文件未提及』,不得自行補充、不得推測、不得編造數字或價格」。
2. **換模型審稿(A 產 B 審)**:審稿人拿到任務原始要求 + 草稿 + **內部文件本身**,逐條核對每個事實/數字/價格/承諾能不能在文件裡找到出處,找不到就當編造。判定落 `data/free-quota/reviews/`。
3. **紅線寫進每一張題目卡**,不是寫在這裡:不得出現價格/成本/毛利/客人姓名/店名/電話;不得出現可辨識人臉(抓周與日照中心強制寫 no identifiable faces);生歌全 instrumental 不寫歌詞;敏感值只寫「此處有敏感值,已略」。
4. **產出一律標「草稿未審」**,檔頭自動帶上日期、模型名與 item,對外發布永遠是人。

## §5 誠實項

1. **250 件/天的機制驗過,但整天的量還沒實跑過**。今天實跑的是 `bash free_quota_daily.sh 3 50` 這一班:**7 題、5 件扇出 job-run、20 次呼叫,三種扇出各自產出檔案都在**。整天 1000 次會不會撞到 OpenRouter 免費模型的日上限,**還沒測到牆,現在講得出來的只有「上限已放到 1100、撞牆會自動收工」**。
2. **每件 4.0 次呼叫是今天單一樣本**(5 件 / 20 次)。樣本小,免費鏈的失敗率每天會變,所以 250 件可能落在 700 到 1200 次之間。這個數字要跑滿幾天才算數。
3. **產稿模型會把思考過程寫進產出**。今天三份產出開頭都有「We need to output…」這種英文自言自語,內容本身是對的,但要再加一道去頭處理才適合直接拿去用。
4. **場景 8-19 是規格,不是已上線**。表上標 [待開] 的十二題目前只有欄位定義,沒有 `.job.md`,沒跑過。
5. **六班排程還沒掛上 launchd**,現在要靠手動或另外派工觸發。
6. **`hermes_call.sh` 本身還是沒接讀檔**(#88 照舊開著)。本輪修的是**班表這條通道**(`free_quota_daily.sh`),那條是每天固定產能的主力;`hermes_call.sh` 是隨問隨答的那條,還在零 context 狀態。
