沒有解決,也還是沒有人在管。剛才四個 repo 全部重查一次,數字擺這裡。

handbook 47 條遠端分支,九月碰過的只有 3 條(main、日常那條、codex 的餐飲指南),其餘 44 條放著沒動。investment-os 23 條,main 跟真正在跑模擬倉的 markyang 線分岔 302 比 82,跟今天下午查的時候一模一樣,沒有人去收。agent-bus 只有 main 一條、零分岔,它是反例,因為多台機器一定要交會,有約束就長不出分支。

今天新查到的一條,比分支數更嚴重:claude-daily-operations 根本沒有 main。整個 repo 只有 ops/relocate-register-20260803 跟一條 9/07 的 gpt 線。「出貨只認 main」這條規矩在每天寫紀錄的那個 repo 裡是無法執行的,因為沒有那條線可以認。

真的解決的只有一件:handbook 的 main 跟日常分支維持在 0 比 0。但那是每一輪手動推上去維持的,不是制度,人不在就會重新分岔;而且還有三支腳本把分支名寫死(free_quota_daily、a0_sheet_probe、yt_daily_hermes_meeting),日常工作搬不回 main。

順帶更正一個自己報過的數字。之前說 cdo 大約 150 個檔案沒進版控,那是用 git status 的行數算的,而 git 會把整個資料夾折成一行。實際展開是 1444 個檔案。其中 560 是可重生的快取、445 是處理標記,這一千多個該進忽略清單不是進版控;真正該留痕跡的紀錄類大約 356 份:每日營運紀錄 258、共治逐字稿 36、codex 工單 31、hermes 值班表 13、審查案卷 18。

本輪實際做的一件事:把整合官每週該做的那份掃描寫成程式 branch_governance_check.sh,一次掃四個 repo 報分支數、老分支數、分岔數、未進版控檔數,任何一項不合格就退出碼 1。理由很簡單,設一個沒人來當的角色等於沒有人在管,角色會缺席,腳本不會。誠實講一句:這支在本輪沙箱裡執行被擋下來,上面那些數字是用單一 git 指令一條一條查出來的,腳本本身還沒自跑過。

要一句話的兩件,都建議做:一是 cdo 開一條 main,把現在那條 ops 線的內容當第一版推上去,之後才有東西可以認;二是那 356 份紀錄現在入版控,共用 repo 依規不自行動手。
