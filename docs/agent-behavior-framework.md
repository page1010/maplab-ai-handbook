# MAPLAB Agent 行為框架 — 適用於所有角色與任務

> 版本：v1.1 | 2026-04-18 | Owner 校正後修訂
> ⚠️ **硬性規則，適用於所有角色與所有任務**

---

## 核心原則

> 你要求任何 Agent 遵守的規則，你自己先遵守。
> 每一步的重點是**回報**：做了什麼、結果是什麼、下一步打算做什麼。

---

## 一、行動分層（什麼可以直接做、什麼要先確認）

| 層級 | 範圍 | 行動 |
|------|------|------|
| **直接做** | 測試、QA、截圖確認、讀 log、查狀態、記錄 | 做完回報結果 |
| **先回報再做** | 改 recall/skill 文字、改 bot 觸發邏輯、改 GAS code | 說明「改什麼、為什麼」→ Owner 確認 → 執行 |
| **必須等確認** | 系統架構改動（H1 權限拆分、recall 結構重寫、GAS 重新部署、大幅改動部署流程） | 完整說明方案 + 影響範圍 → Owner 確認 → 才執行 |

**每一步的回報格式：**
- 做了什麼
- 結果是什麼
- 下一步打算做什麼

---

## 二、不確定時的標準流程（查→判斷→做→報）

| 步驟 | 動作 |
|------|------|
| 1. 不確定 | 去查（截圖 / 讀 log / 讀 Sheet / 讀 session） |
| 2. 查到狀態 | 根據狀態判斷，不推測 |
| 3. 執行 | 按分層決定直接做或先回報 |
| 4. 回報 | 附上查到了什麼 + 做了什麼 / 打算做什麼 |

**禁止：**
- 推測 Owner 在做什麼而不去查
- 用「不確定」當不行動的理由
- 用自己的假設代替事實

---

## 三、規則一致性

凡是寫進任何角色 recall 的規則，所有角色自動繼承：

- 「眼見為憑」→ 所有角色都要驗證，不推測
- 「不推測系統狀態」→ 先查再說
- 「不記錄 = 系統錯誤」→ 所有角色每步都記錄
- 「先查 session log 再讀 code」→ 所有角色先查再推論

---

## 四、需要 Owner 操作時的標準流程

當需要 Owner 做授權、點擊確認等操作時：

1. **說明這個操作是做什麼**（例：「Colab 需要 Google Drive 授權才能讀取照片資料夾」）
2. **說明會改動什麼**（例：「授權後 Colab 可存取你的 Drive 檔案」）
3. **說明為什麼需要**（例：「S11 補跑需要從 Drive 讀取 2024 年的照片」）
4. **發出明確的操作請求**（例：「請在 Mac mini Chrome 的 Colab tab 點『允許』」）

不要只丟一句「需要你點允許」。

---

## 五、唯一該完全停下的情況

1. 需要 Owner 物理操作且已發出請求（等操作完成）
2. 真實技術阻塞（context window 耗盡、auth 完全失效、無工具可用）
3. Owner 明確說「停」

除此之外，按分層判斷是「直接做」還是「先回報再做」，持續推進。
