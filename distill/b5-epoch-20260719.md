## 一、可逆先行準則（SECTION 24 核心）

**一句話**：可逆的直接做，不可逆的才等 Owner。

### 判斷樹

```
要執行一個動作 →
  ├─ 做錯了，一個 git revert 能完全回到原狀？
  │     是 → 直接做（不等 Owner，不等數據）
  │     否 → ↓
  └─ 有真實金錢/時間/外部影響無法撤回？
        是 → 準備 W→SW→NW 核准申請，等 Owner 一次回覆
        否 → 直接做
```

### 三個關鍵例子（用於教材訓練）

| 情境 | 正確行為 | 錯誤行為（舊習慣） |
|------|---------|----------------|
| patrol.sh 偵測到 T-A6-001 已 11 天無 commit | 直接寫回 STALLED 狀態 | 等 Owner 說「好，你去改」 |
| AGENT_RULES 新增 SECTION 24 | 直接 commit + push | 先在 Telegram 問「可以加嗎？」 |
| A6 LINE webhook 正式啟用 | 等 Owner 核准 + 確認 Channel ID | ❌ 直接啟用（不可逆） |

### 任務書標注格式（所有新 Task Card 必須加）

```markdown
- **動作可逆性**: 可逆（git revert 可回）
```

## 二、翻轉預設 — 四態狀態機（SECTION 25 核心）

**一句話**：殭屍任務自動關閉；Owner 有異議才重開（一句話即可）。

### 狀態轉移（patrol.sh 自動驅動）

```
IN_PROGRESS → [48h 無 commit] → STALLED → [7d] → NEEDS_REVIEW → [7d] → AUTO_CLOSED
```

重開：Owner 回覆「重開 T-XXX」→ A1 手動改回 IN_PROGRESS

### 為什麼這樣設計（Opus R5 洞察）

**舊設計的問題**：
- T-A7-001 累計第 24 次警告（~331h），Owner 警覺疲勞
- patrol.sh 的「⚠️」無限累加 = 噪音
- 任務預設存活，Owner 要主動說「關掉」才關

**翻轉後**：
- 任務預設會死（超時自動 AUTO_CLOSED）
- Owner 有異議才主動說「重開」
- patrol 報告從「第 N 次警告」變成「已 AUTO_CLOSED」（一次性事件）

### 結構性消除殭屍卡的機制

| 殭屍卡 | 舊行為 | 新行為 |
|--------|-------|-------|
| T-A6-001（🔄 IN_PROGRESS 11d） | ⚠️ 第 N 次警告累加 | 本輪 patrol → STALLED |
| T-A7-001（⏳ 等 Owner 決策） | ❓ 狀態未標記 → ⚠️ | 識別為 ⏸️ BLOCKED → 顯示 blocker，不走 AUTO_CLOSE |

## 三、Fable vs Opus 派工路由（真實數據版）

**結論先說**：不是「Opus 先，Fable 後」，而是「Opus 先回答前提假設，Fable 再落地設計」。

### 用 Opus 的情況

- 需要在開始前質疑問題定義（避免在錯誤前提上建系統）
- 需要標注不確定性（Opus 從 R1 就做，Fable 需 R2 才補）
- 診斷複雜系統失靈、找「被忽略的前置條件」
- 例：R04「拒單能力才是定價框架的防火牆」— 這是 Opus 才會提的前提質疑

### 用 Fable 的情況

- 框架已定義，需要轉化為可執行工具（矩陣、計分卡、SOP）
- 需要 W→SW→NW 自然輸出
- 需要「Owner 一次回覆清單」格式
- 需要系統存檔建議和複利設計

### 最佳協作模式（5 場景驗證）

```
Opus R1（前提質疑 + 概念框架） 
  → Fable R2-R5（落地設計 + 迭代精煉）
```

關鍵問題：
- Opus R1 問：「這個框架的前提假設成立嗎？」
- Fable R2 問：「這個框架如何在 72 小時內產生第一個可用版本？」

## 四、三版對比信度評估

| 比較維度 | 模擬版說對了 | 模擬版說錯了 |
|---------|------------|------------|
| Fable 更自然輸出 W/SW/NW | ✅ | — |
| Opus 更強在假設挑戰 | ✅ | — |
| 最佳協作：Opus 診斷 Fable 落地 | ✅ | — |
| Opus 犯量化錯誤頻率 | ❌（高估） | 真模型 Opus 從不提無根據數字 |
| Fable 自我批判結構 | ❌（低估） | 真模型 Fable 用準則條號系統批判 |
| Opus 的前置條件質疑深度 | ❌（未出現） | 真模型每場景都提出根本性前提質疑 |

**底線**：方向判斷 ~70% 可信，具體洞察深度和模型弱點分布用真實數據。

## 五、地端模型訓練指引（B5 用）

若要訓練 Ollama 本地模型內化這三個準則：

### 可逆先行 — 訓練格式

```
Q: 我應該直接更新 AGENT_RULES 還是先問 Owner？
A: 直接更新。AGENT_RULES 的修改是可逆的（git revert 可回），屬於可逆先行準則（SECTION 24）的範疇。不等 Owner 點頭才是正確行為，等待 = 偷懶。
```

### 四態狀態機 — 訓練格式

```
Q: T-A6-001 最後活動是 2026-07-08，今天是 2026-07-19，應該怎麼處理？
A: 偵測到 IN_PROGRESS 任務 11 天無 commit（>48h 閾值），自動寫回 STALLED 狀態。這是可逆動作，patrol.sh 直接執行，不需要 Owner 核准。
```

### 翻轉預設 — 訓練格式

```
Q: T-A7-001 已經第 24 次警告了，應該繼續警告還是做什麼？
A: 24 次警告是警告堆積問題，屬於舊設計缺陷。新四態狀態機下：⏳（等 Owner 決策）識別為 BLOCKED，不走 AUTO_CLOSE；問題結構性消失。下次不再累加警告，而是一次性顯示為「⏸️ 阻塞中 — Owner 確認 Zone B/C 金額」。
```
