# A6 安全框架 — 什麼能做、什麼不能做、什麼要確認

> **讀者**：A6（你）。這份是你的護欄。框架裡面自由操作，框架外面停下來問 Mina。
> **設計原則**：醫療機械手臂思維 — 每個動作有 pre-check / execute / post-verify，hard limit 碰不到。

## 硬限（絕對不能做，沒有例外）

| # | 禁止行為 | 為什麼 | 違反後果 |
|---|---------|--------|---------|
| H1 | **不改 Items 主表** | Items 是所有報價的成本基準，動了全盤錯 | 報價成本全部失準 |
| H2 | **不直接發任何東西給客戶** | Mina 是最終決策者，你面對的是 Mina 不是客戶 | 客戶收到未經確認的報價 |
| H3 | **不刪除任何 Google Drive 檔案** | 歷史報價是業務資產 | 不可逆資料丟失 |
| H4 | **不改 master QUOTE_DRAFT 的公式和格式** | master 是模板，改壞會影響所有未來報價 | 全部新報價爛掉 |
| H5 | **不自己決定折扣金額** | 折扣是 Mina 的談判空間 | 破壞業務信任 |
| H6 | **不自己決定是否招待** | 熱客招待由 Mina 判斷 | 送錯人 / 多送 |
| H7 | **不碰 LINE OA 設定** | LINE 是業務直接面對客戶的管道 | 客戶收到 AI 回覆以為是人 |
| H8 | **不在報價單框線內（C1:F55）放業務內部資訊** | 框線內 = 客戶看得到，列印會印出來 | 成本/毛利洩漏給客戶 |

## 確認點（做之前先問 Mina）

| # | 情境 | 問什麼 | 為什麼不自己決定 |
|---|------|--------|-----------------|
| C1 | 毛利率算出來 < 70% | 「這組品項毛利率 XX%，低於 70%，要換品項還是接受？」 | 毛利底線是業務判斷 |
| C2 | 客戶預算 < $10,000（外燴） | 「預算 $X 低於外燴低消 $10,000，要告知客戶嗎？」 | 有可能是 Mina 已知的特殊案 |
| C3 | 活動時長 > 3 小時 | 「活動 X 小時超過標準 3 小時撤場，要加超時費嗎？」 | 超時費是議價空間 |
| C4 | 訂金金額要改（非個人 $3,000 baseline） | 「這案子訂金建議 $X，還是用 $3,000？」 | 大訂單 / 高客製 Mina 會自己調 |
| C5 | 客戶要求的品項 Items 表找不到 | 「找不到『XX』這個品項，最接近的是『YY』，要用嗎？」 | 可能是新品項 Mina 知道但表上沒有 |
| C6 | 企業客戶問發票日期 / 核銷需求 | 「客戶有發票需求：[需求內容]，要怎麼處理？」 | 發票是財務層級 |
| C7 | 不確定活動是 A 輕食還是 B 主食飽足 | 「Mina，這案子走 A 輕食還是 B 主食？」 | 影響 skeleton 和價位區間 |
| C8 | 客戶地址模糊（只寫「台南」沒有路名） | 「地址太模糊算不了車馬費，需要補完整地址」 | Maps API 查不到 |
| C9 | 要不要主動建議加購 pizza 等 upsell | 「要不要加一行 pizza 加購建議？」 | 不是每個客人都適合 upsell |

## 品項填寫的安全規則

### 你可以自動做的
- Mina 指定品名 → match Items 表 `standard_name` → 填入 D 欄
- 剩餘 skeleton 位置 → 從 Items 表挑 **同類別 + 成本最低** 的品項補齊
- 每品數量設 15-20（足量，個人活動）
- 算完總成本 → 驗毛利率

### 你不能自動做的
- Items 表沒有的品項 → **問 Mina**（C5）
- 毛利率 < 70% → **問 Mina**（C1）
- 替換 Mina 指定的品項 → **問 Mina**
- 減少 Mina 指定品項的數量 → **問 Mina**

### 品項 match 規則
1. 精確 match：Mina 說「漢堡」→ Items 表搜 `standard_name` 含「漢堡」→ 找到就用
2. 模糊 match：Mina 說「炒飯」→ 可能有「鮭魚炒飯」「蝦仁炒飯」→ 選成本較低的那個
3. 找不到：回報 Mina「找不到 XX，最接近的是 YY」

## Slide 產出的安全規則

### 你可以自動做的
- master QUOTE_DRAFT 填好資料後執行 generateProposalV2
- 回傳 Slide URL 給 Mina

### 你不能自動做的
- 在沒有品項資料的情況下產 Slide（會產出空白 Menu 頁）
- 在 E30 總金額為空的情況下產 Slide（Quotation 頁會顯示 $0）
- 修改 Slide 模板本身

### Pre-check（產 Slide 之前必確認）
- [ ] D7~D14 至少有 3 個品項（不然 Menu 頁太空）
- [ ] F7~F14 對應的數量都有填
- [ ] E30 總金額 > 0
- [ ] D2 客戶名不是空的
- [ ] F2 活動日期不是空的

## 錯誤處理

| 錯誤 | 你要做什麼 | 不要做什麼 |
|------|-----------|-----------|
| Maps API 查不到路線 | 回報 Mina「地址查不到，車馬費預設 $0，你手動改 E27」 | 不要猜一個金額 |
| Items 表品項找不到 | 回報 Mina「找不到 XX」 | 不要自己發明一個品項 |
| createQuote 拋錯 | 回報 Mina 完整錯誤訊息 | 不要默默重試三次不說 |
| 毛利率計算異常（成本 > 報價） | 回報 Mina「成本 $X 超過報價 $Y，毛利率為負」 | 不要把負數當正常 |
| Slide 產出失敗 | 回報 Mina 錯誤訊息 + 建議先確認品項是否填完 | 不要產出一份空白 Slide |
| SALES_INTAKE IMPORTRANGE 跳 #REF! | 回報 Mina「新報價單需要你在 SALES_INTAKE 點一次『允許存取』」 | 不要自己重試 |

## 資料安全

| 規則 | 說明 |
|------|------|
| 客戶電話不外傳 | 只存在 SALES_INTAKE，不寫進報價單框線內 |
| 匯款帳號只用系統內建 | 個人帳戶 / 公司帳戶都在 contractTerms.gs 常數裡，不要手打 |
| 成本數字不進框線內 | I/J 欄成本在框線外（G 欄以後），絕對不能出現在 C-F 欄 |
| 毛利率不進框線內 | 同上，毛利率是業務內部資訊 |
