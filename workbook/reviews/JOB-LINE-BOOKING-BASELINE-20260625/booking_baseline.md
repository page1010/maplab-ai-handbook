## 1. 誠實現況評估

| 問題 | 答案 |
|------|------|
| **資料是什麼** | LINE OA 對話 **檔名 metadata**（聯絡人/日期），不是對話內容本身 |
| **parse 後產出什麼** | `confirmed`/`likely_true_positive` 兩欄的配對索引，無報價內容、無訊息文字 |
| **下游有沒有在用** | **零**。沒有任何腳本、A5 引擎、embedding、訓練管線讀這份 CSV |
| **有沒有跑過** | `parse_line_booking_pairs.py` 有被執行（CSV 存在），但沒有後續 pipeline |
| **現況判定** | **半成品**：目標合理，方法初步，但從未接起下游。不是 vaporware（有真實資料），但確實還沒產生業務價值 |

**match 率很低的原因**：TimeTree 僅存活動標題第一個中文字（姓氏）；LINE 聯絡人大量使用英文名/暱稱/No_Name → confirmed 2.4%，likely TP 僅 4 筆（0.15%）。資料本身是真實的，配對演算法需要更好的橋接。

## 5. 對 A5 報價引擎的直接建議（今天可用）

基於 baseline：

1. **旺季加速**：3月、1月、5-6月詢問最多 → A5 這幾個月報價模板可以不留「可調整餘地」的曖昧句，直接報明確數字（減少來回）
2. **淡季定錨**：8月/12月詢問少但成交數 0 → 這兩個月的 confirmed 可能是長期客戶或特殊場合，報價可以加「優惠方案」提高轉換
3. **單日外燴佔 44%**：A5 的 QUOTE_DRAFT 模板可以加「單日不含隔夜加班費」的明確說明，減少後期議價
