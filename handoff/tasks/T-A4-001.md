                ## ⛔ GPS 細分技術問題說明（S5.5 / S6.5 全部年份適用）

                ### 問題根本原因

                GPS 細分的資料來源是 **Google Photos Takeout 的 JSON sidecar 檔**。每張照片有一個對應的 `.json` 檔，內含拍攝地點座標：

                ```
                IMG_20220101_120000.jpg       ← 圖片（已上傳 Drive）
                IMG_20220101_120000.jpg.json  ← GPS metadata（★ 沒有上傳 Drive）
                ```

                ### 為什麼 JSON 沒有上傳？

                Owner 執行 Google Photos Takeout 時，只把**照片本身（.jpg/.mp4）**上傳到 Google Drive。Takeout 壓縮包裡的 `.json` sidecar 檔**沒有一起上傳**。

                這些 JSON 檔存在 Owner 本機的 Takeout 解壓縮目錄，但 Colab 只能讀 Drive，讀不到本機。

                ### Colab 實際執行結果

                ```
                S5.5 GPS cell 執行輸出：
                JSON map built: 0 files   ← Drive 裡找不到任何 .json 檔
                ```

                → 程式找不到 GPS 座標 → 所有照片全標 `no_gps` → 細分無意義

                ### 解決方案（三選一，需 Owner 決定）

                **方案 A（推薦）：把 Takeout JSON 上傳到 Drive**
                - 估計數量：~60,584 個 JSON 檔（每張照片一個）
                - - 操作：本機選 Takeout 解壓目錄的 `.json` 檔 → 上傳指定 Drive 資料夾
                  - - 優點：一次解決所有年份
                    - - 缺點：需要 Owner 手動上傳，檔案多但每個很小（~2KB）
                     
                      - **方案 B：跳過 GPS 細分，全標 no_gps**
                      - - 操作：在 ASSET_LOG 中把所有日常照片的 subdivision 欄位填 `no_gps`
                        - - 優點：立即可執行，不影響主分類流程
                          - - 缺點：失去 home/shop/other 的區分能力（但 Owner 說照片清洗不急）
                           
                            - **方案 C：從 EXIF 讀取（不依賴 Takeout JSON）**
                            - - 原理：圖片本身的 EXIF metadata 也有 GPS，用 Python `PIL/Pillow` 直接讀圖
                              - - 優點：不需要上傳 JSON，資料已在 Drive
                                - - 缺點：需要重寫 GPS cell 程式碼（約 30 行），且部分照片 EXIF 可能被 Google 清除
