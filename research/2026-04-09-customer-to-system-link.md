## 已挖到的事實（確定）

### F1 — LINE OA 自動回應有完整選單樹（這就是現成的客戶分流）

LINE OA 收到任何訊息會先丟一個 9 選項分流選單，要客戶按 #1~#9：

| # | 類別 | 用途 |
|---|------|------|
| #1 | 週歲派對／收涎／慶生／性別揭曉派對 | 個人慶祝（最常見） |
| #2 | 新居入厝／家庭聚會／長輩壽宴 | 家庭聚餐 |
| #3 | 婚禮外燴／證婚／Candy Bar／迎賓甜點桌 | 婚禮 |
| #4 | 開幕茶會／企業活動／品牌發表／公司午茶餐敘／商務會議／記者會／餐酒品酒會 | 企業 |
| #5 | 外帶自取菜單-派對鹹甜點心／野餐派對盒 | 外帶 |
| #6 | 到府私廚料理（西式排餐饗宴／親子互動教學） | 私廚 |
| #7 | 市集／品牌異業合作邀約 | B2B 合作 |
| #8 | 如果你想要的不在選單裡 | Other |
| #9 | 客製化精緻點心盒 | 點心禮盒 |

**意義：客戶在第一輪互動就被分到 9 類之一，這是「活動類型」最早的訊號**，比 SALES_INTAKE 自己再問一次更早。系統應該直接吃這個分類欄位而不是讓業務手動再選 dropdown。

### F2 — 客戶按 #1（週歲）後，系統自動丟出 8 欄需求表單

LINE 自動回應在客戶按 #1 後，立刻推送一份「請填以下表單」的訊息，問：
- 活動類型
- 活動日期
- 活動時段
- 地點（城市/區域/地址或場租空間）
- 場地型態（室內冷氣房 / 半戶外 / 戶外）
- 預估人數
- 餐點形式（A 輕食茶點 / B 正餐主食飽足感）
- 額外是否加購背板+氣球佈置

**意義：客戶在 LINE 那邊已經被結構化問過 8 個欄位**。如果我們把這些欄位的回答抓下來自動寫進 SALES_INTAKE，業務在 Telegram 那邊就不用再問一遍。**目前 QuoteForm 缺：地點型態、餐點形式 A/B、是否加購佈置 — 這三個欄位 LINE 已經在收**。

### F3 — 真實案例：伶（2025/10/30 19:33 首次互動）

從 LINE chat CSV 第 2 號檔案（`2_20251030_20251030_伶.csv`）抓到的完整互動：

```
19:33:14  Account 自動回覆：歡迎詞 + 9 選單
19:33:46  伶：「1」
19:33:58  伶：「#1」
19:33:59  Account 自動回覆：週歲派對表單（8 個問題）
19:35:16  伶：「抓周 114/4/12 下午 台南 室內冷氣房 2[TRUNCATED]」
```

**觀察：**
- 客戶 1 分鐘內就收到表單 → 系統已經非常前置
- 客戶用「自由文字」回答，不是 1-by-1 答題：「抓周 114/4/12 下午 台南 室內冷氣房 2...」
- 一行字裡包含：活動類型（抓周）+ 日期（114/4/12 = 2025/4/12，民國年）+ 時段（下午）+ 地點（台南）+ 場地（室內冷氣房）+ 人數（2x...）
- **業務需要的是一個 NLP 解析器**，把這串自由文字拆成 SALES_INTAKE 的 8 個欄位。這 90% 是 regex + 關鍵字 matching 可以搞定，不需要 LLM。

### F4 — 歷史報價檔名本身就是結構化資料

`歷史報價單` folder 根目錄的檔名命名規則（從 30+ 樣本歸納）：

```
[月/日] [外燴|外帶|戶外|...] [人數|每人單價] [客戶名|活動描述|金額]
```

範例：
- `4/16外燴 15人菜單7500`  → 4/16 / 外燴 / 15人 / 7500 元
- `5/15外燴10人菜單`        → 5/15 / 外燴 / 10人
- `5/22 900/人`             → 5/22 / 900 元/人
- `8/9 40人12000水姑娘`     → 8/9 / 40 人 / 12000 元 / 客戶「水姑娘」
- `9/11戶外婚禮15000`       → 9/11 / 戶外 / 婚禮 / 15000 元

**意義：可以從檔名直接歸納出大量「客戶 × 預算 × 人數 × 活動類型」的真實樣本**，不用打開檔案就能建一張對應表。先把 932 個檔案的檔名 scrape 下來做檔名統計，比逐個讀內文快 100 倍。

### F5 — 業務的客單價區間（從檔名抽出來）

只看根目錄前 30 個檔案就可以歸納：
- **單人單價** 範圍：400 / 600 / 700 / 750 / 800 / 900 / 930 / 1000 / 1150 元/人
- **總價** 範圍：7500 / 12000 / 15000 元
- **常見人數**：10、15、40 人

→ 對應到 quote-pricing-logic.md 的「毛利 70%」和「單人 4 樣」可以反推：
- 400/人 × 4 樣 = 100 元/樣 → 食材成本約 30/樣 → 等於低成本品項（如餅乾、薯條）
- 1150/人 × 4 樣 = 287 元/樣 → 食材成本約 86/樣 → 中高階品項（牛排普切塔、布朗尼）

→ 業務的單價跟食材組合是有對應的，可以建一張「單價區間 → 推薦品項組合」對照表。

### F7 — 時間權重原則（Owner 2026-04-09 親口給）

> **MAPLAB 有產品迭代與進步，所以日期越靠近，越接近現行運作中的版本。**

實作含義：

| 資料時間段 | 權重 | 用途 |
|-----------|------|------|
| 2025-10、2025-11 + 根目錄散落檔 | **高（採信為當前 SOP）** | 訓練 A6 自動推品項的主力資料 |
| 2025 上半年 | 中高 | 對照當前 trend，但已可能稍有偏差 |
| 2024 年 | 中 | 看長期 trend，不直接套用 |
| 2023 年 | 低 | 只看「曾經的樣子」，不拿來推今天 |

**衝突解決規則**：新舊資料矛盾時 → 信新的 → 把舊的標為「歷史快照」而不是「錯誤」。
**檔案歸檔線索**：根目錄散落 ≈ 還沒歸檔 ≈ 最新；年份子資料夾 ≈ 已歸檔的歷史。優先讀根目錄。

> 來源：Owner 2026-04-09 親口告知「我們也有產品迭代與進步」。後續所有量化分析（單價區間、品項組合、毛利率）都要附時間戳，否則沒意義。

## 從 5 份 2025 sample 抽出的核心 patterns

### P1 — 品項類別固定四大類

每份報價的菜單區塊都是：
1. **創意異國鹹食小點 / Finger Food / 主廚開胃小品**（5-10 品）
2. **主食**（0-3 品，看活動類型，週歲較少、入厝較多）
3. **手作精緻甜點 Dessert**（2-4 品）
4. **飲品**（1-2 桶，6L 或 8L 玻璃桶裝，或檸檬紅茶）

### P2 — **實際品項數規律**（推翻先前假設）

| 活動類型 | 鹹食 | 主食 | 甜點 | 飲品 | 總品項數 |
|---------|------|------|------|------|---------|
| 入厝派對（吳方潤） | 8 | 0（融入鹹食） | 2 | 1 | 10–11 |
| 開幕茶會（保險） | 5 | 0 | 6（含 2 加購）| 1 | 11–12 |
| 週歲（怡瑩） | 6 | 0 | 4 | 1 | 10–11 |
| 性別揭曉（匿名） | 5 | 0 | 4 | 1 | 10 |
| 週歲（曹家瑄） | 5 | 3 | 2 | 1 | 10–11 |

**重點：實際運作中，所有報價的品項數都落在 10-12 之間，不是 quote-pricing-logic.md 寫的「6-12 視人數變動」**。應該更新該檔案。

### P3 — 服務費收費規則跟先前理解相反

- **B2B 開幕茶會 → 10% 服務費 = 0**（保險營業部那份）
- **個人 性別揭曉 → 10% 服務費 = 2,100**（匿名 30 人那份）

**這跟我先前在 contractTerms.gs 寫的 B2B/B2C 邏輯相反**，需要驗證後修正。Possible 解釋：
- B2B 客戶通常價格較硬，業務願意吃掉 10% 服務費換成交
- 個人客戶收 10% 反而是默認，業務有時免收當作折扣

### P4 — 車馬費規則驗證 OK

- 嘉義五顯館 → 3,000 ✓ 跟 SOP「外縣市 $3K-$4K」一致
- 台南市內各點 → 0 ✓ 跟 SOP「市內免費」一致
- 高雄大社（怡瑩 Jolin）→ 在 sample 裡沒看到車馬費明示，待驗證

### P5 — 訂金規則：個人 $3,000 固定

5 份 sample 裡個人客戶都是固定 $3,000 訂金，**不是按比例**！跟 contract-terms-v4.md 寫的「訂金 50%」完全不符。實際 30K 訂單只收 3K = 10%。

→ **contract-terms-v4.md 的訂金條款（50%）是錯的，業務真實做法是固定 3,000 訂金**。要更新。

### P6 — 熱客招待是品項註記，不是獨立區塊

- 「墨西哥莎莎玉米片（招待）」直接寫在品項旁邊
- 不是另開一個 section 叫「熱客招待」
- 業務的做法：在組好的菜單裡選 1-2 個品項加註「（招待）」，金額不另算

→ **目前 QUOTE_DRAFT row 17-19「熱客招待」獨立區塊的設計跟業務實際做法不一致**，這就是為什麼 Owner 要 hide rows 17-19 — 因為業務根本不用那個區塊，他們直接在品項裡標記。

### P7 — 客戶飲食禁忌欄位

5 份 sample 裡 4 份有「客戶禁忌/偏好」備註：
- 「不要牛肉」
- 「兩三款不要起司」「大人居多」「指定鴨胸串」
- 「肉類部分不要牛羊」
- 「中西合併」

**目前 QuoteForm 沒有這個欄位**，業務寫在報價單外的備註欄。應該加一個 `dietary_notes` text input。

### P8 — 業務手動回購客比對

`2025/1/25怡瑩菜單` 內嵌 2024/7/27 同客戶前次訂單在右半欄。業務做法：**手動翻舊報價、截圖貼上、對比新舊菜單**。

→ 這就是回購客識別的人工版。系統可以做的：用客戶名/電話 fuzzy match SALES_INTAKE 歷史，自動把 last quote URL 帶到新報價的「上次訂單」欄位。

### P9 — 客製化主題品項是常態

- 性別揭曉 → 「雙色派對甜甜圈架」（主題色）
- 週歲 → 「派對甜甜圈架」（小孩主題）

業務有「主題客製品項」這個 SKU 概念，不是固定品項。Items 表可能要加 `theme_variant` 欄位。

### P10 — 一次性餐具/打包盒附贈規則

- 30 人活動：附贈一次性餐具 40 組 + 打包盒 15 個
- 餐具組數 ≈ 人數 + 30%
- 打包盒 ≈ 人數的一半

可程式化的規則。

## LINE 對話抽出的 A6 訓練重點（T16-T25）

基於完整對話樣本，補充到第一層 A6 思維訓練清單：

### T16 — 業務有「pax × budget tier → 品項 skeleton」的固定公式

從吳惠珍案例看出：
- **20 人 + 輕食茶點 = 8 品項，結構固定 3 鹹 + 2 開胃 + 3 甜 + 1 飲**
- 預算區間 $15K-$24K，tier 不同時品項**數量不變**，改成**升級食材等級**
- 這**推翻 T2「品項隨廚房出」的簡化理解**。實際是：
  - **Skeleton 固定**（3+2+3+1 這種比例是算好的）
  - **具體品項彈性**（哪三道鹹點、哪三道甜點，隨當天廚房/主題）
- A6 訓練：**學 pax → skeleton 對應表**，但不學「固定哪幾道菜」

### T17 — 客戶典型對話 4 階段

1. **招呼 + 表達意願**（「你好/我有外燴需要」）— 碎訊息常見
2. **時間 + 類型濃縮回覆**（「1/12 下午5點 新厝慶生 住家 半戶外 20人」）— 客戶一行塞 6 個欄位是常態
3. **價位與細節談判**（素食 / 桌子 / 服務費 / 加購）— 5-10 個往返
4. **預約登記**（姓名電話）→ 菜單確認（照片 + 文字說明）

A6 要知道現在對話在哪一階段，對應不同策略。

### T18 — 業務補問工具箱（10 個常見補問）

從多份 sample 歸納 Mina 的追問：
1. 地點「哪一區」（細化到區）
2. 桌子自備嗎 / 要租借嗎
3. 含服務費嗎（確認價格含義）
4. 有任何禁忌食材嗎
5. 有無素食需求
6. 有無樓層 / 電梯（2F 加搬運費）
7. 室內/半戶外/戶外（影響擺設）
8. 預約姓名 + 電話（登記用）
9. 預算區間（決定 tier）
10. 幾個人（pax）→ 套 skeleton

A6 收到不完整 intake 時就從這 10 個補問抓最重要的問。

### T19 — 業務的「價位區間 + 食材升級」定價模型

不是「品項固定、算成本、加毛利」，而是「品項數固定、依預算挑食材等級」：
- 20 人輕食 = 8 品（固定）
- $15K → 基礎食材（一般鹹點 / 普通甜點）
- $20K → 中階（加入魚子醬 / 干貝）
- $24K → 高階（和牛 / 松露）

→ A6 的「自動推品項」應該是「自動推 skeleton + 依 budget 挑食材等級」，不是「依成本湊品項」。

### T20 — 場次緊迫感 urgency 收單是人工 tactic

「這天場次較多，最晚今天收單」
→ 業務面對未成交客戶的關單技巧
→ A6 **不應自動用**（避免虛假行銷），但**要知道這是人類業務會做的動作**，可以 surface 給業務 as 建議「要不要發緊迫性訊息？」

### T21 — 業務有「服務範圍 7 點」固定模板

Mina 標準訊息：
