### 1.1 機制澄清（影響整個流程設計，必讀）

**部位互抵 ＝ 沖銷平倉**，不是「部位留著、保證金打折」。
所以「互抵釋放保證金」是對的 —— 保證金之所以回來，是因為**部位沒了**。
這同時代表：**互抵就是出場動作**，而且是零成本出場（免費免稅）。

對照 ORB 的成本：一般出場要付手續費＋期交稅（微台來回 12 點）。
走互抵出場，這一段省掉 —— 這正是此策略的結構性價值所在。

因此正確的循環順序是：

```
鎖一組價差(兩腳同時進) → 等價差收斂 → 互抵沖銷(零成本出場) → 整組保證金回籠 → 再鎖下一組
```

而不是「鎖倉 → 互抵放保證金 → 在同一組上加掛」。

## 3. 介面規格（三段式狀態機）

### 狀態 A：偵測（全自動，模擬環境現在就能做）
- 讀兩腳即時報價 → 算淨價差 ＝ 毛價差 − 進場全成本
- 報價品質閘：任一腳報價過期或跳空異常 → 不發訊（防幽靈價差）
- 淨價差 ≥ 門檻 且 保證金餘額足一組 且 在 08:45–14:00 互抵窗口內 → 進狀態 B

### 狀態 B：推播給 Owner（推播內容規格）
必含六欄，缺一不發：
1. 兩腳代碼與各自報價
2. 鎖住點數與換算 TWD
3. 本組佔用保證金、佔用後餘額
4. **互抵窗口剩餘分鐘數**（14:00 關窗）
5. 進場全成本（已扣）
6. 若此刻反向出場 vs 互抵出場的成本差

### 狀態 C：收斂核對與下一組
- Owner 回報已互抵 → 我重新讀帳本確認兩腳部位歸零、保證金回籠數字對得上
- 對得上才允許評估下一組；對不上一律停手並回報差異（不自行推論）
