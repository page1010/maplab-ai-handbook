【Fable5 本人・同 session 續接】圖看了,是那篇介紹 OmniRoute 的 IG 貼文——把 Claude Code 接多家模型、額度用完自動切下一家。你前一則的推論我現在完整對上了,結論一致:不裝,自管更好。

拿三問加你的模型顧慮檢它,三個死穴:
1 它讓「額度用完」這個事件決定用什麼模型,不是讓任務性質決定。切到 DeepSeek 或 Kimi 的那一刻,主腦窗就被靜默降級,而且事後查不出哪段決策是哪個模型做的。圖書館員貼錯標籤可以追回重做,主腦降級做錯決策是直接虧。
2 它站在金鑰路徑上:一個第三方 repo 代管所有 provider 的 API key,踩憑證紅線加注入風險,而且來源是留言索教學的導流貼文,可信度層級最低。
3 它解的痛我們已有解:額度紀律管高階窗、便宜機械活走 hermes 免費鏈。router 這個概念我們其實已經有了——hermes 就是我們自管的 router,差別是有金測集考試、有溯源欄、金鑰不出門。

所以你的結論就是正解:同樣是多模型調度,自管的 hermes 是「我們挑模型、有考試、可追溯」,OmniRoute 是「額度挑模型、無考試、不可追溯」。這筆已登進總索引標「評估後不採用」,附否決理由,以後看到同類工具直接比對這條。
