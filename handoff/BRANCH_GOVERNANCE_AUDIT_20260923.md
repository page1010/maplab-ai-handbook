## 二、四個具體症狀

1. **出貨沒有版本可選。** investment-os 要壓縮給客人,main 停在 7/16、缺 82 個 commit;
   跑著模擬倉的 markyang 分支缺 302 個。**兩條都不是可出貨版本**,而這件事在有人真的要打包前
   不會有人發現。

2. **巡邏在一條沒人做事的線上宣告 all clear。** handbook `origin/main` 最近的提交
   **全部是 `patrol(a1): daily check — all clear`**,而所有實際產出長在 chore 分支上
   (領先 588 個 commit)。實證:今天建的稱謂表 `NAMING_GLOSSARY.md`
   **在 origin/main 上不存在**(`git cat-file -e origin/main:NAMING_GLOSSARY.md` → 128)。
   **這條巡邏目前的 all clear 沒有意義,因為它看的不是有人在改的那份。**

3. **「凡走過必留下痕跡」目前是破的。** cdo 約 150 個檔案從未進版控,包括
   `state/hermes_duty/`(值班表)、`state/operations/2026-08-04 ~ 09-23`(每日紀錄)、
   `state/cogov_transcripts/JOB-codex-crosscheck-*`(36 份交叉稽核逐字稿)。
   **這些痕跡只有一份,活在這台 Mac 的硬碟上。** 連續 49 輪 `git pull cdo` 失敗是同一個原因。

4. **反例證明單線可行。** agent-bus 只有 main、零分岔——因為多台機器必須在同一條線上交會,
   不交會當場對不上。**約束存在時就不會長分支;會長分支是因為沒有約束,不是因為工作性質特殊。**

## 三、根因一句話

**分支是免費的,合併是要付代價的,而沒有任何角色被指派去付那個代價。**
每個角色都往旁邊長一條,沒有人往回收;久了 main 就退化成「最舊的那份」,
而不是「最確定的那份」。

## 四、建議制度(對應 Owner 提的四件事)

1. **出貨只認 main**:要壓縮給客人的就是 main 上的某個 tag,其他分支一律當未定稿。
2. **每條分支一張卡**:誰的、做什麼、預計哪天併回。沒有卡的分支到期封成 tag ——
   **封存不是刪除,tag 本身就是痕跡**(對應「凡走過必留下痕跡」)。
3. **收斂要有一個人**:固定一個整合官角色,每週一次掃全部分支、列重複功能、裁定收成一條,
   Owner 只看一張表。**這是目前唯一缺的角色**(見 `NAMING_GLOSSARY.md` 的角色名層)。
4. **重複功能先讓機器判**:同一個檔案被兩條分支改到,git 自己算得出來
   (`git diff --name-only origin/main...<branch>` 取交集),先出清單;真的兩套實作才需要人裁。
5. **好的抉擇也入檔**:採用哪條、為什麼採用、**被否決那條的理由**,寫進決策檔並在合併紀錄裡
   引用(對應「留下好的抉擇也是痕跡的一環」)。
