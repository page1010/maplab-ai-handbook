## INCIDENT-001: Takeout ZIP 被刪導致 EXIF metadata 永久遺失

- 日期: 2026-03-17
- Agent: A4 (Pipeline Agent)
- 嚴重性: HIGH
- 資料影響: mina 帳號 122,200 張照片的 JSON sidecar metadata 永久遺失

### 事件經過
1. A4 從 Takeout ZIP 解壓時，只提取了圖片/影片檔案（jpg, heic, mp4 等）
2. **沒有同時提取 JSON metadata 檔案**（每張照片的 EXIF、GPS、時間戳記）
3. 在大局觀分析時，A4 發現需要提取 JSON metadata
4. 同時，A4 建議用戶「清空垃圾桶回收 348GB」
5. **用戶清空垃圾桶時，原始 Takeout ZIP 一起被刪除**
6. 再回頭提取 JSON 時才發現 ZIP 已經不存在

### 根本原因
- **流程規劃不完整**: 解壓時沒有一次性提取所有需要的檔案
- **建議清除前沒有確認依賴**: 建議刪除資源前，沒有檢查是否還有資料需要從中提取
- **缺乏「不可逆操作」的警覺**: 清垃圾桶是永久性的，應該在所有提取工作確認完成後才建議

### 實際損失
- Google Photos Takeout JSON 包含: GPS 座標、拍攝時間（精確到秒）、相機型號、原始描述
- 這些資訊現在只能靠 Gemini Vision 推測，準確度下降
- 年份仍可從資料夾名稱取得，但精確日期和地理位置資訊遺失

### 防範規則（所有 Agent 必遵守）

**RULE: 不可逆操作檢查清單**
> 在建議用戶執行任何「不可逆操作」（刪除、清空、覆蓋）之前，必須：
> 1. 列出該資源中所有尚未提取/備份的資料
> 2. 確認所有提取工作已完成並驗證
> 3. 明確告知用戶「刪除後無法復原」
> 4. 如果不確定，建議「先不要刪」

**RULE: Takeout 解壓必須全量提取**
> Google Takeout ZIP 解壓時，必須同時提取：
> - 所有圖片/影片檔案
> - 所有 .json sidecar metadata 檔案
> - 不要只選擇性提取，因為 ZIP 可能隨時被刪除

**RULE: pagewu1010 Takeout 處理時的 SOP**
> pagewu1010 的 5 個 ZIP（187GB）還在。處理時必須：
> 1. 一次性提取所有檔案（包含 .json）
> 2. 提取完成後，逐一驗證 JSON 數量是否合理
> 3. 驗證完成後，才可以建議刪除 ZIP
> 4. ZIP 刪除前再次確認：「所有需要的資料都已提取？」

## 教訓摘要（快速參考）

| # | 教訓 | 規則 |
