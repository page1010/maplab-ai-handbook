二,為什麼會自己登出,我先講我知道的和我不知道的。

知道的:Claude 的登入是 OAuth 授權,有期限,到期就要重新授權一次。這台機器的排程吃的是設定檔裡一把長效 token,跟你在電腦前互動時用的那組不是同一個東西。所以會出現「你自己用沒事、排程卻說沒登入」這種不一致。

不知道的:我還沒證實今天這一次到底是不是 token 過期。有一個線索跟「單純沒登入」對不上——它跑了四分鐘才死。沒登入通常是幾秒內就被擋掉,不會跑那麼久。所以現在有兩個可能:token 真的過期,或是跑起來之後才出別的錯。

我不編。要查清楚才報。查 auth 狀態的那道指令這一輪被權限擋住,我換別的路徑往下查。

三,hermes 為什麼不能代登入。

hermes 是一個接 OpenRouter 的模型路由,它手上只有 API 金鑰,沒有瀏覽器、沒有鍵盤、也不持有 Anthropic 的帳號。Claude 的登入是要在瀏覽器裡按「同意授權」,那不是它能做的動作。

更重要的是第二層:代登入等於要把你的帳號授權交到 agent 手上。你綁 Google 帳號之後,那把鑰匙後面接的是你整個 Google。帳密、授權碼、cookie 這三樣我一律不碰,這條不因為方便就鬆。

所以答案不是「hermes 現在做不到、以後補上」,是「這件事不該由 agent 做」。

四,那要怎麼不要每次都卡在這。這才是該解的題。

第一,排程用的憑證跟你互動用的分開,而且用長效的那種,不要讓排程去吃會過期的那把。

第二,加到期前預警。現在是排程死掉我們才知道,應該是到期前就先叫。這跟我昨天寫進制度的那條同一個道理:等壞掉才響的警報太晚了。

第三,失敗訊息要分得開。今天 log 只吐一行 Execution error,完全看不出是沒登入還是別的錯,這種 log 等於沒有 log。要改成明確寫出是哪一類失敗。
