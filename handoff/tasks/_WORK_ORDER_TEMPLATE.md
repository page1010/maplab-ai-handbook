## 派工欄位（五欄硬性 ＋ 可逆性）

- **結果**: 〈填這裡〉
- **指標**: 〈填這裡〉
- **期限**: 〈填這裡〉
- **權限**: 〈填這裡〉
- **回報點**: 〈填這裡：何時回報／回報寫哪個檔／done 的定義／blocked 的定義〉
- **動作可逆性**: 〈填這裡：可逆 / 不可逆〉

## 每欄怎麼填才算填了

| 欄 | 不算填 | 算填 |
|---|---|---|
| **結果** | 「處理 gold 清洗」（任務名稱） | 「`~/.maplab/gold_replies/` 下有 N 筆通過去雜訊規則的配對，規則寫在 RULES.md，任何人重跑得到同一批」（完成後世界長什麼樣） |
| **指標** | 「做好」「優化」 | 可量的數字或可驗證輸出：「287 筆全跑過、被剔除的每筆有剔除原因碼」「`python3 -m unittest tests.test_x` 全綠」 |
| **期限** | 「盡快」 | 絕對時間：「2026-09-24 12:00 前」。跨夜工作要寫清楚是哪一天。 |
| **權限** | 空白（＝executor 只能猜，猜錯就是越權） | 逐條寫：能動哪些路徑／能不能 commit／能不能 push／能不能重啟哪個 process／哪些絕對不准碰（金鑰、真倉、對外發布一律不准） |
| **回報點** | 「做完跟我說」 | 回報時機＋落點＋**兩個終態的定義**（見下節）。 |
| **動作可逆性** | 空白 | 可逆／不可逆。**不可逆的工作不得派給實作性 agent**，回到 Owner（SECTION 27 第五節 S3 門檻）。 |

### 終態必須先定義好（第五欄的真正重點）

派工單上就要寫死這兩句，不留給 executor 自由心證：

- **done ＝** 〈填這裡：什麼條件全部成立才可以寫 done；通常是「指標欄那句話被驗證過，且驗證證據落在某個檔」〉
- **blocked ＝** 〈填這裡：卡在什麼上面才算 blocked，且 blocked 必須寫出卡點與已嘗試過什麼〉

**為什麼寫這麼硬**：win-01 曾七張卡連續 picked-and-failed，真因不是 agent 不夠好，而是**終態沒定義**——executor 結束沒寫終態、finalizer 只能補 blocked、blocked 又被壓住不重試，於是七張卡靜靜死掉。缺第五欄的代價就是這個。

### 沒有終態回寫 ＝ 沒完工

- executor 不論成敗都要回寫終態；**跑失敗也要寫 blocked，不准靜默結束**。
- 回報落點要是檔案（task card 本身／`state/` 下的 log／agent-bus outbox），**不是只在對話裡講**。
- 終態之後的狀態維護走 SECTION 25 四態 FSM（IN_PROGRESS → STALLED → NEEDS_REVIEW → AUTO_CLOSED）。
