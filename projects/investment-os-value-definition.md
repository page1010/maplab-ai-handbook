# Investment OS 到底要帶來什麼

> 建立：2026-07-12 | A0 派工 Phase B 第一性思考
> 用途：後續所有角色走查、功能決策、通知設計的量尺
> 紅線：本文件全程不下單、不建模擬單、不給個股買賣建議

---

## 核心問題（Owner 原話）

「以這次半導體產業的修正為例，有什麼先知道，有什麼可以動態調整，要不要建議我降部位，面板與 mail 通知給我會不會更好」

這個問題的本質是：**Investment OS 的存在讓 Owner 的決策比沒有它快多少、準多少、安全多少？**

---

## 五個核心交付（Investment OS 的唯一存在理由）

一頁結論：Investment OS 不是「20 個輸出的系統」，是「讓 Owner 每天回答 5 個問題的速度從 30 分鐘 → 3 分鐘」的工具。

### 1. 今天可不可以動（每日可動性判斷）

**Owner 需要**：進入任何研究、報告之前，先有一個「今日可動 / 不可動 / 只觀察」的明確答案，以及為什麼。

**量尺**：輸出第一屏就回答，不需要讀三個報告再拼湊。

**半導體修正教訓**：如果系統在修正前兩週已有「不可動：Firstrade 槓桿 1.99x + US tech 82.7% 集中度 CRITICAL + 制度不明確」的判斷，Owner 的決策框架完全不同。

---

### 2. 風控閘門狀態（集中度 / 槓桿 / 現金）

**Owner 需要**：集中度（US tech/semi 佔比）、槓桿（Firstrade x）、現金水位是否在安全區。超標時不是「提醒一下」，是「列三個選項 + 後果，等 Owner 選一個」。

**量尺**：每個指標有明確門檻，門檻是 Owner 設定的規則，不是系統猜的。超標 = 強制通知，決策永遠在 Owner。

**半導體修正教訓**：82.7% US tech CRITICAL 已在 exposure_ledger（2026-07-01）。問題是這份資料只在 Telegram operator bot 裡，沒有一個「這個閘門紅了 → 通知格式 + 三選項」的完整路徑。

---

### 3. 世界觀錨定（正在驗證的終局假設）

**Owner 需要**：目前在驗證的終局假設最多 1-2 個（例如「AI infra 今年進主升段」），每個有明確的「證實條件 / 證偽條件 / 目前進度」。

**量尺**：所有左側、右側、籌碼、新聞訊號都要能對照終局假設打分（支持 / 反對 / 不相關）。沒有終局假設的系統產出的都是事件追逐，不是結構投資。

**半導體修正教訓**：功能審計確認，20 個輸出裡沒有一個服務四層篩選的第一層（世界觀/終局資格）。系統只能告訴 Owner「今天哪支漲停」，不能回答「半導體這個終局假設還站不站得住腳」。

---

### 4. 訊號新鮮度保證（過期不上 Owner 介面）

**Owner 需要**：知道哪個維度的資料是新的、哪個是過期的，過期的不應出現在決策介面（應標示「不可用」而不是靜默顯示舊數據）。

**量尺**：每個維度有明確的「最大可接受過期時間」；超過則降級顯示 stale alert，不讓 Owner 用過期資料做決策。

**半導體修正教訓**：
- 左側報告最後更新 2026-05-23（修正前 ~49 天停更）
- 右側報告最後更新 2026-05-19（~54 天停更）
- FRED 總經資料靜默過期（pitfall #184）
- shadow_findings.jsonl 自 2026-06-02 斷供

這些資料在 Telegram/Dashboard 上沒有顯式標示過期，Owner 可能以為系統還在運作。

---

### 5. Owner 決策紀錄（觀察/等待/排除都算決策）

**Owner 需要**：每一個「我決定什麼、為什麼、什麼情況下這個決策失效」的紀錄，讓下一次覆盤能回答「我是對的嗎、為什麼對/錯、下次要改什麼」。

**量尺**：不只有下單才算決策。「我選擇觀察」「我排除這個候選」也是決策，一樣要留紀錄和失效條件。

**半導體修正教訓**：系統能告訴 Owner 今天有什麼，但無法回答「上週的多頭決策，在這次修正後，thesis 有沒有失效」。

---

## 四層篩選框架（Owner 的判斷語言）

所有角色的產出都應服務這四層：

```
第一層（世界觀）  → 這個產業是否在 3 年以上大趨勢中？有沒有終局題材？
第二層（左側）   → 法人籌碼是否異動？非共識機會是否浮現？
第三層（右側）   → 價格、成交、題材是否已開始確認趨勢？
第四層（風控）   → 集中度 / 槓桿 / 現金是否允許行動？
```

**任何角色的產出，如果對四層篩選框架的貢獻是零，就是在消耗注意力。**

---

## 三個禁區（Investment OS 永遠不做的事）

1. ❌ 給個股買賣建議 → 所有建議設計成「規則觸發 → 通知 + 三選項 + 後果說明」
2. ❌ 把過期資料包裝成有信心的結論 → 過期降級、標示不可用、不顯示在決策介面
3. ❌ 把社群/KOL 傳聞升格為主攻訊號 → 社群永遠進 quarantine，獨立驗證後才算 evidence

## 使用方式（後續走查量尺）

每個角色走查時問三個問題：

| 問題 | 對應五大項目 |
|------|------------|
| 這個角色的產出，Owner 在哪個場景下用到？ | #1 可動性 / #2 風控 / #3 世界觀 |
| 如果這個角色停跑 30 天，Owner 感覺得到嗎？ | #4 新鮮度 |
| 這個角色的輸出，有沒有讓 Owner 做一個決策、留一個紀錄？ | #5 決策紀錄 |

投資者價值評分（1-5星）：
- ⭐⭐⭐⭐⭐ 直接服務可動性判斷 / 風控閘門（必須保留且優先修復）
- ⭐⭐⭐⭐ 服務世界觀或提升決策品質（保留）
- ⭐⭐⭐ 訊號來源或研究輔助（保留，可在資源緊張時降頻）
- ⭐⭐ 基礎設施或低信訊號（保留但不加功能）
- ⭐ 間接貢獻（基礎設施，維持現狀）
