# A6 實際使用場景與角色定位

> **來源**：Owner 2026-04-09 + 5 份完整 LINE 對話分析（L1-L5）+ 14 份歷史報價 sample
> **核心定位**：A6 不是 Mina 的替身，是 **Mina 的報價加速器**。Mina 繼續接案對話，A6 在背景產出 80 分報價單，Mina 微調後就能發。

---

## 為什麼需要 A6

**痛點（Owner 親口）**：Mina 接案同時要跟客戶對話 + 算報價 + 開菜單 + 發合約。**如果 Mina 在忙，報價就延誤**。

- 真實案例（吳惠珍 L1）：客戶 9:36 確認「給我 2 萬菜單」→ Mina 10:02 回傳菜單（**等了 25 分鐘**）
- 真實案例（洪炳輝 L5）：客戶 12:49 確認價位 → Mina 22:17 回傳菜單（**等了 9.5 小時**）
- 真實案例（李晴宜 L4）：客戶 22:20 確認「15000+10%」→ Mina 23:33 回傳菜單（**等了 73 分鐘**）

**如果 A6 在背景 3 秒內產出 80 分報價單**，Mina 就從「等我空了才能開菜單」變成「看一眼、改一兩樣、就能發」。報價速度從**小時級降到分鐘級**。

---

## A6 不做什麼

| A6 不做 | Mina 繼續做 | 為什麼 |
|---------|------------|--------|
| 跟客戶 LINE 對話 | ✅ Mina 對話 | 信任 + 人情味 + 業務判斷 |
| 決定收不收訂金 / 折扣多少 | ✅ Mina 判斷 | 談判是業務核心能力 |
| 挑具體品項（哪道鹹點、哪款甜點） | ✅ Mina 或主廚決定 | 品項隨廚房當天有什麼 |
| 場地佈置風格判斷 | ✅ Mina + 陳列規劃師 | 需要看照片 + 經驗 |
| 判斷客戶是否值得熱客招待 | ✅ Mina 判斷 | 關係 + 直覺 |

## A6 做什麼（80 分報價單 = 框架全填好，品項待 Mina 挑）

### 場景 1：Mina 收到客戶 LINE 填完表單

**客戶行為**（從 L1-L5 歸納）：
- 按 #1~#9 選分類 → 收到該分類的表單 → 填 8 欄回覆
- 或直接打自然語言（「你好我有外燴需要 1/12 20 人」這種碎訊息）

**Mina 目前的手動流程**：
1. 看客戶填的 8 欄 → 腦中歸類（活動類型 + 形式 A/B + pax + 預算 tier）
2. 手打「20 人份輕食 $15,000~$24,000 起，共八款...」的報價介紹
3. 手貼「服務範圍 7 點」模板
4. 等客戶回預算 →  叫主廚開菜單 → 截圖菜單照片 → 傳給客戶
5. 客戶確認 → 發匯款資訊 + 收訂金 + 發「陳列規劃 3 件事」模板

**A6 可以自動做的（介入點 = Step 2~4）**：

| Step | 原本 Mina 手動 | A6 自動化 |
|------|---------------|----------|
| 2 | Mina 手打報價介紹 | A6 **秒產**：根據 pax + 形式 A/B 帶 skeleton + 價位區間 → 生成「報價介紹訊息」草稿 |
| 3 | Mina 手貼服務範圍 | A6 自動 append「服務範圍 7 點」模板 |
| 4a | 客戶回預算 → 告訴主廚 → 等主廚開菜單 | A6 在客戶說預算後 **秒產 80 分報價單**（createQuote 帶 skeleton 品項框架 + 車馬費 + 搬運費 + 條款 + 訂金金額），**品項欄位留空格讓 Mina 或主廚填** |
| 4b | Mina 截圖菜單照片傳客戶 | 先不做 — Mina 改完品項後自己截圖（或未來 A6 自動產 Slide 截圖） |
| 5 | Mina 手貼匯款資訊 + 收訂金 + 陳列 3 件事 | A6 在報價單確認後自動觸發「匯款資訊 + 陳列規劃 3 件事」模板（post-sale 自動化） |

**80 分報價單 = Mina 打開 copy 就看到什麼？**

```
QUOTE_DRAFT copy 已填好：
✅ D2 客戶名 / F2 活動日期 / D3 地址 / F3 時間 / D4 活動類型 / F4 人數
✅ D5 活動名稱 / F5 餐點總件數（A6 自算 pax × 4）
✅ E25 租借長桌公式（自動）
✅ E27 車馬費（Maps 自動算）
✅ E28 搬運費（表單選的）
✅ C32/C33 合約條款（自動帶對應 to_c/to_b 版本 + 訂金金額）
✅ K10/L10 飲食禁忌備註
✅ K11-L13 車馬費/搬運費計算備註
✅ N5 報價狀態 = 報價中
✅ N7 付款狀態 = 未匯款
✅ N9 版本 = v4
⬜ D7~D14 品項名稱 = **空白（Mina 或主廚來填）**
⬜ F7~F14 品項數量 = **空白**
⬜ E30 總金額 = **空白（Mina 確認後填）**
```

Mina 打開後只要做：
1. D7~D14 填品項名稱（dropdown 選或打字）
2. F7~F14 填數量
3. E30 填總金額
4. 看一眼條款 + 車馬費 + 搬運費是否正確
5. 完成 → 截圖 → 發客戶

**從等菜單的 9.5 小時 → 填品項的 5 分鐘**。

### 場景 2：Mina 接到企業客戶 (#4)

**差異**：
- 企業版表單多問：預算 / LOGO 小插旗 / 主辦或協辦
- Skeleton 不同（看 B2B + 人數 + 形式）
- 條款 = to_b_deposit 或 to_b_full
- 服務費「已含」隱藏
- 匯款資訊 = 圖蕾實業社公司帳戶

**A6 自動做的跟場景 1 一樣**，只是 contractTerms.gs 和 quoteHelpers.gs 的 output 自動切換。Mina 不用額外操作。

### 場景 3：Mina 在忙 + 客戶已確認預算

**真正的加速點**：

```
客戶 LINE 12:49 確認「預算 3 萬」
   ↓
LINE webhook 自動寫 CONVERSATION_LOG
   ↓
A6 偵測到「預算確認」訊號（關鍵字：「預算」「萬」「辦到好」等）
   ↓
A6 自動呼叫 createQuote({
  客戶名: 洪炳輝,
  日期: 10/25,
  活動: 入厝,
  形式: B 主食飽足,
  pax: 30,
  地址: 台南安南區安興街,
  ...
})
   ↓
3 秒後，80 分報價單 copy 產出 → URL 推到 Mina 的 Telegram
   ↓
Mina 手上有空時（可能 22:17）打開 → 填品項 → 截圖 → 發客戶
```

**延誤從 9.5 小時 → Mina 下次有空的那一刻（可能 5 分鐘後）。**

---

### 場景 4：客戶還沒確認預算，A6 先備好

Mina 送出報價介紹後，客戶還在消化期（1-7 天）。

A6 可以**先根據價位區間的中間值**產一份「預設版報價單」存在 Drive，等客戶確認實際預算後 Mina 微調。如果客戶說的預算跟預設接近（±20%），Mina 連品項都不用大改。

## Mina 的固定模板庫（A6 應該會呼叫的 snippets）

### 模板 1：報價介紹（pax + 形式帶入後自動組）

```
{pax}人份{形式名}形式
餐檯整體規劃的費用是 ${price_low}~${price_high} 起皆可製作，
預算與食材用料規劃會不同。
（上述費用另有 10% 服務費）  ← B2B 時改為「已含服務費」

共提供{item_count}款 季節性鹹甜{形式描述}+飲品
（{skeleton 描述}）

我們的西式外燴餐點在餐檯上的呈現方式，
大多以單份的精緻方式提供{B主食時加：，主食與肉類類型為盤裝分食享用}；
外燴服務主要都是主廚客製化的餐點，
目前無提供制式化的菜單
👉會以報價後，您所選的價位跟活動性質為您開製作菜單！
```

### 模板 2：服務範圍 7 點

```

2.「陳列規劃師」會於行前以每場菜單來客製設計餐檯擺設
3.專人現場餐檯盤器陳列

7.相對人數一次性餐具
⚠️不包含擺放餐點的長桌（可租借，$350/張）
```
