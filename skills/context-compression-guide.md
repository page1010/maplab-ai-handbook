# Context Compression Guide — 防 Prompt Too Long 技能書

版本：v1.0 | 建立：2026-03-15 | 維護者：A1 Handbook Agent

本文件提供 MAPLAB AI 系統在對話 context 接近上限時的**標準應對流程**。
目的：讓任何 Agent 接手時不需重新摸索，直接按 SOP 執行。

完整系統規則見：AGENT_RULES.md

---

## 為什麼會發生 "prompt too long"？

Claude 的 context window 有限（約 200,000 tokens）。  
一個 session 中若包含：
- 大量工具呼叫結果
- 多次 read_page / get_page_text 的完整輸出
- 長篇文件多次讀取
- 多輪來回對話 + 系統摘要

就會觸發 **"prompt is too long: XXXXX tokens > 200000 maximum"** 錯誤。

---

## 預防策略（主動）

### 1. Session 規劃前先估算

開始大任務前評估：
- 預計讀幾個文件？（每個約 2,000–10,000 tokens）
- 預計幾輪工具呼叫？（每次結果約 500–3,000 tokens）
- 對話本身約幾輪？（每輪約 500–2,000 tokens）

**原則：單一 session 建議處理不超過 5–7 個文件**

### 2. 讀文件優先用 get_page_text 而非 read_page

| 工具 | Token 消耗 | 適用場景 |
|------|-----------|---------|
| get_page_text | 低（只取文字）| 讀取文件內容 |
| read_page (all) | 高（含DOM結構）| 需要互動元素 |
| read_page (interactive) | 中（只取可互動）| 需要操作表單/按鈕 |

**→ 讀文件一律用 get_page_text，只在需要互動時才用 read_page**

### 3. Context 達 50% 時主動存檔

估算目前 context 使用量：
- 若已超過 ~100,000 tokens，**立即進行階段存檔**
- 不等使用者提醒，Agent 主動告知並執行存檔

## 應急 SOP（已發生時）

### Step 1：立即停止操作

遇到 "prompt is too long" 錯誤時：
1. 停止目前動作
2. 不要嘗試繼續執行（會繼續失敗）

### Step 2：生成階段存檔摘要

主動輸出以下格式的摘要給使用者：

```
## 階段存檔 — [日期時間]

### 已完成
- [任務1]：[狀態]
- [任務2]：[狀態]

### 進行中（中斷點）
- [當前任務]：[卡在哪一步]
- [待執行動作]：[下一步是什麼]

### 未完成
- [任務3]：[尚未開始 / 等待條件]

### 關鍵狀態
- 重要 URL：[如果有正在操作的頁面]
- 重要數值：[如果有需要記住的資料]
- 注意事項：[任何需要下個 session 知道的事]
```

### Step 3：建議下個 session 的開場語

提供使用者複製用的開場語範本：

```
接續上次任務。
上次進行到：[X]
下一步需要：[Y]
請先閱讀：[相關文件 URL]
```

### Step 4：提醒使用者更新 GitHub

若本次 session 有尚未 commit 的重要中間狀態，  
建議使用者先手動儲存或告知 Agent 優先 commit 已完成部分。

## 技能：精簡讀取技巧

### 避免重複讀取同一文件

```
❌ 錯誤：每次操作前都 get_page_text 整個文件確認
✅ 正確：只在首次讀取，後續用已知資訊操作
```

### 大文件只讀必要段落

```
❌ 錯誤：read_page 整頁（含所有 DOM 元素）
✅ 正確：find() 直接找需要的元素，或 get_page_text + 搜尋關鍵字
```

### 工具結果不重複確認

```
❌ 錯誤：每次 commit 後再 get_page_text 確認內容
✅ 正確：觀察 GitHub 切換回 blob view 即確認成功
```
