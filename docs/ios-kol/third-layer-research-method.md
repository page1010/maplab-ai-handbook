# IOS-KOL Third-Layer Research Method

版本：2026-06-15
Owner：IOS-KOL Influencer Radar Manager
用途：KOL 影片、Podcast、公司 call、供應鏈 memo 與操作筆記的產業研究整理規則。

## 核心原則

IOS-KOL 的任務不是把公開新聞重寫一遍，而是把訊號分層，保留有 edge 的公司與供應鏈情報，同時避免把未公開驗證的數字誤寫成官方事實。

當來源包含研究員跑公司、call 公司、供應鏈回報、BOM 拆解、rack-level 模型、KOL 操作筆記時，必須升級為三層研調輸出。

## 三層定義

第一層：公開可驗證事實

- 公司法說、年報、官方簡報、交易所公告、政府資料、標準組織或公開白皮書。
- 可以寫成「已公開確認」。
- 必須附來源與日期。

第二層：產業結構推論

- 用公開事實推導產業鏈位置、供需瓶頸、替代供應商、capex 方向、ASP/毛利可能變化。
- 可以寫成「由公開資料推論」。
- 必須列出推論橋梁，避免只給結論。

第三層：田野情報與早期訊號

- 研究員公司 call、供應鏈口徑、客戶拉貨、設備 lead time、BOM/rack-level 模型、封測與被動元件通路回報、KOL 的操作筆記。
- 這類數字常常是 edge，不能因為公開資料查不到就丟掉。
- 也不能直接寫成官方事實。必須標記為「第三層情報」並說明驗證狀態。

## 數字標籤

每個重要數字必須至少標一個 tag。

| Tag | 用法 | 寫法 |
| --- | --- | --- |
| `official_public` | 官方或一手公開來源可驗證 | 已公開確認 |
| `public_compatible` | 公開方向一致，但精確數字來自非公開或次級來源 | 公開資料方向相符，精確數字待驗 |
| `company_call` | 研究員跑公司、call 公司、供應鏈訪談 | 第三層公司 channel 情報 |
| `bom_model` | BOM、rack、unit economics 或需求模型推算 | 模型估算，需列假設 |
| `channel_check` | 通路、交期、缺貨、漲價、下修訂單回報 | 早期 channel 訊號 |
| `anomaly` | 與公開資料明顯衝突或量級可疑 | 需回頭核對單位、期間、公司範圍 |

## 必備輸出格式

三層研調稿至少包含以下段落。

1. `來源地圖`
   列出影片、截圖、PDF/memo、公司 call、公開來源與日期。沒有日期就標 `date_missing`。

2. `數字驗證矩陣`
   欄位固定為：主題、數字、原始來源、公開驗證、tag、採用方式、風險。

3. `六大主題或產業鏈拆解`
   對每個主題分開寫：供需變化、誰受惠、誰受壓、下個驗證點。

4. `第三層 Radar`
   只放公開資料不容易看到的早期訊號，例如供應鏈缺料、lead time 拉長、客戶設計變更、單機價值量變化、稼動率變化。

5. `反證條件`
   寫出哪些事件會推翻目前判斷，例如官方 capex 未上修、關鍵元件交期回落、客戶拉貨延後、替代技術進入量產。

6. `下次 call 問題`
   把不確定處變成可問公司的問題，不要只留成模糊疑問。

## 2026-06-15 範例規則

TSMC capex：

- 官方公開資料若只有 USD 52-56B，就標 `official_public`。
- 若研究員 memo 寫 USD 58B，不能刪掉；標 `company_call` 或 `public_compatible`，寫成「第三層上修訊號，尚未見官方公開確認」。

CoWoS / SoIC / CoPoS 月產能：

- 若來自公司 call 或供應鏈模型，標 `company_call`。
- 用來判斷先進封裝設備、載板、封測、測試、材料的下一波受惠順序。
- 不可寫成官方公告產能。

MLCC、鋁質電容、電感、DrMOS、BBU、HVDC：

- rack-level 單機價值量與用量屬於 `bom_model`。
- 若同時看到缺貨、交期拉長或漲價，另加 `channel_check`。
- 結論要寫到「誰的規格升級、誰的產能最難補、誰只是量增但價格不一定漲」。

Nexperia USD 75B：

- 若與公開 revenue 量級明顯不符，標 `anomaly`。
- 先核對是否為單位錯誤、公司範圍錯置、出貨顆數、TAM 或期間混用，不可直接採為營收事實。

## 品質標準

好的 IOS-KOL 研究整理要同時做到三件事：

- 保留第三層 edge，不把研究員的田野數字磨平成公開新聞摘要。
- 清楚標記可信度，不把未公開數字偽裝成官方事實。
- 把情報轉成投資或產業驗證問題，讓下一次 call、追蹤、Dashboard 或 Telegram digest 有明確方向。
