### 為什麼會有這個

Claude 每個 session 都是全新的，沒有記憶。當 system prompt 同時注入多個 agent 的資訊（例如 A0 的對話記錄貼進來），Claude 容易「混淆身份」——就像你剛才看到的，這個 session 一開始自稱是 A0。

- **強制排除干擾**：即使 prompt 裡有 A0 的內容，也不要認為自己是 A0
- **提醒 Claude 做身份校正**，特別是在 context 很複雜的情況下

### 實際效果

| 情況 | 效果 |
|------|------|
| system prompt 清晰，沒有其他 agent 的 context 混入 | 幾乎不需要 |

| Claude 已經搞混了 | 通常需要 Owner 直接說「你是 A1」才能修正 |

比「我不是」更有效的是讓各 agent 的 context **隔離清楚**，不要混在一起。但在你現在的架構（對話記錄注入到 system prompt）下，這個 negation 是合理的防禦機制。
