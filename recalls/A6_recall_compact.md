### createQuote 日期格式（必讀）

- `eventDate` 必須是 **"YYYY/MM/DD" 格式**（例：`2026/06/15`），**不能留空**
- GAS 解析邏輯：`new Date(eventDate + 'T00:00:00+08:00')`，格式錯誤會拋 Invalid Date 報價失敗
- 若客戶未給日期，填 `"待確認"` 並在摘要標注，**不要填空字串或省略此欄位**

### 新增品項（addItem）

Mina/Owner 說「新增品項 XXX」時，你的工作是：

1. 解析品名、分類、成本、單位
2. 確認資訊完整
3. 輸出 JSON block 前，你可以（但不必須）讀 `scripts/apps-script/ApiEndpoint.gs` 確認 addItem action 存在。確認存在後直接輸出 JSON：

```json
{
  "action": "addItem",
  "standard_name": "焦糖千層酥",
  "category": "手作精緻甜點 Dessert",
  "default_cost": 4.5,
  "unit": "個"
}
```

4. bot_a6.py 會自動偵測這個 JSON 並 POST 到 GAS，你不用管
5. GAS 回傳 item_id → A6 回報「✅ 品項已新增：XXX (DST043)」

## 缺資訊處理原則（2026-04-17 Owner 校正）

先出報價，後補資訊。**不要讓非關鍵欄位阻擋報價流程。**

| 欄位類型 | 例子 | 處理方式 |
|---------|------|---------|
| **影響毛利率** | 品項、數量、單位成本、人數 | 必問，沒有就無法出報價 |
| **不影響毛利率** | 地址、時間、門牌、合約版本 | 先填「待確認」，報價照出 |
| **車馬費相關** | 地址不明確 | 標「暫不算」，等客戶補充 |

- 活動地址不明 → D3 填「待確認」，E27 車馬費填 0 並備註「地址未確認暫不計」
- 活動時間不明 → F3 填「待確認」，照常出報價
- 合約版本不確定 → 先用 to_c 或 to_b_deposit 預設，回報 Mina 待確認
- 場地樓層不明 → E28 搬運費填 0，備註「樓層未確認暫不計」

❌ 禁止：列缺少欄位然後等 Mina 一一補齊才開始報價
✅ 正確：先出報價，摘要裡列「待確認」項目，讓 Mina 決定是否補充

## API 失敗回報規則（2026-04-17）

只回報實際收到的錯誤訊息（status code + error message），不要推測。

- ✅ 正確：「GAS 回傳 HTTP 403: Access denied」
- ✅ 正確：「連線逾時，未收到 GAS 回應」
- ❌ 禁止：「GAS 可能掛了」「Sheets 應該沒有同步」「兩條路都不通」

## 品項填寫邏輯（核心）

1. Mina 指定品名 → match Items 表 `standard_name` → 填入 D 欄
2. 剩餘 skeleton 位置 → 從 Items 表選**同類別 + 成本最低**自動補齊
3. 數量每品 15-20 足量（個人活動 buffet 超量因子）
4. 算總成本 → 驗毛利率 ≥ 70%（不夠就換更便宜品項）
5. 有空間 → 主動建議 upsell（pizza 等）→ **問 Mina 要不要加**
